## 3. 🔴 그래도 목표에는 못 갔다 — 그게 이 문서의 결론이다

[M7 §3](../design/M7_웨이크워드_재구축.md)의 전시회 목표는 **FA ≤ 1회/시간 · FRR ≤ 10%** 다.
**FA 목표는 못 갔다.** 도달할 수 있는 가장 낮은 예산이 **5회/시간**이고 그때 FRR 12.6%다.

📌 다만 이전 진단이 크게 움직였다. 9/18 실측은 *"임계를 0.30~0.99 어디로 옮겨도 FA 목표에
두 자릿수 배수로 못 간다 — 가장 좋은 0.99 에서도 **26.3회**, 그 대가로 FRR **35.9%**"* 였다.

| | 2026-09-18 | **2026-09-28** |
|---|---|---|
| 도달 가능한 가장 낮은 FA | 26.3회/시간 | **5회/시간** |
| 그때의 FRR | 35.9% | **12.6%** |

**오탐 예산과 놓침이 동시에 5배·3배 좋아졌다.** 진단(*"아키텍처가 아니라 데이터"*)이
맞았다는 증거이지만, **목표에 닿았다는 뜻은 아니다.**

## 5. 🚨 자에서 결함 둘을 고치고 나서 잰 숫자다

| | 무엇 | 왜 중요한가 |
|---|---|---|
| ① | 홀드아웃이 **이름 문자열**로 사람을 셌다 | `김예은` · `김예은(다시)` 가 **두 사람**으로 잡혔다. 한쪽이 학습·한쪽이 검증에 들어가면 [M7 §5-2](../design/M7_웨이크워드_재구축.md)가 막으려던 **«같은 편향의 거울»** 이 된다 |
| ② | **구간 0인 화자**가 홀드아웃에 뽑힐 수 있었다 | `나나` 가 뽑히면 «4명 뗐다»고 적히고 실제로는 3명이다 — 분모가 조용히 줄어든다 |

그리고 홀드아웃 4명(`녹음자1 · 녹음자3 · 녹음자5 · 녹음자9`)은 **옛 모델도 새 모델도 본 적이
없는 사람들**로 골랐다. 옛 모델이 학습했던 6명이 섞이면 «전»이 부당하게 좋아 보인다.

## 7. 다시 재는 법

```bash
conda activate pluiz
python scripts/ingest_wakeword.py --holdout 4 --seed 2     # 화자 단위로 4명 뗀다
python scripts/train_wakeword.py --jobs 0                   # 약 17분
python scripts/eval_wakeword.py --model services/wakeword_model_candidate.npz --holdout-only
python scripts/eval_wakeword.py --compare services/wakeword_model_candidate.npz \
       --soak data/soak_16k.wav                             # 🔴 진짜 판정
```

⚠️ **현황을 볼 때는 `npm run pull` 이 먼저다** — `--list` 는 로컬 폴더만 센다.
