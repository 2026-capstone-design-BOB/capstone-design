## 0. 한 줄

**가설이 맞았다.** 시연 5장면(*"블루투스 어디서 켜?"*)이 UIA로 **0.26초 · 토큰 0 · 정확한 좌표**로 풀렸고,
**켜져 있는지까지 알았다.** 지금 우리 Vision 경로는 **평균 4.0초 · 화면 1장 · «추정한 위치예요»** 다.

---

## 1. 어떻게 쟀나 — **`pluiz` 환경은 안 건드렸다**

| | |
|---|---|
| 환경 | `scratchpad/uia-venv` (격리) · `uiautomation` + `comtypes` |

| 대상 | 이미 열려 있던 **Edge** · 잠깐 연 **설정** · 잠깐 연 **메모장**(열고 닫음) |
| 성격 | **읽기 위주.** 클릭은 한 번도 안 했다 |

## 2. 📊 실측 — 숫자

| 무엇 | 결과 |
|---|---|
| COM 초기화(`import`) | **147 ms** — 프로세스당 1회 |
| Edge 트리 훑기 | **415 ms** · 360개 방문 · **이름 있는 컨트롤 78개** · 클릭 가능 51개 |
| 설정 트리 훑기 | **260 ms** · 167개 방문 · 이름 있는 컨트롤 74개 · **토글 3개** |
| 이름으로 찾기 | **0.01 ms** (메모리 검색) |
| 패턴 조사 340개 컨트롤 | 0.79 s |
| **TextPattern 본문 읽기** | **0.8 ms** |

### 🚨 UIA는 **컨트롤 이름을 한국어로 그대로 준다**

```
새 탭         ButtonControl   (2648,0)  64x82
뒤로          ButtonControl   (0,88)    72x64
탭 닫기       ButtonControl   (2592,24) 32x32
설정 및 기타(Alt+F)…          (2852,88) 72x64
```

🔑 **이게 제일 큰 함의다.** *"뒤로 가기 눌러줘"* → **«뒤로»** 는 **글자 맞추기**다.
**화면을 볼 필요도, 모델을 부를 필요도 없다.**

## 3. 🎬 **시연 5장면을 그대로 재현했다** — 이게 결정적이다

*"블루투스 어디서 켜?"* 를 UIA로 풀어 봤다(`ms-settings:bluetooth` → 트리 훑기 → 토글 찾기).

```
🔘 Bluetooth        ButtonControl   (2633,432) 132x80   상태=1  ← 켜져 있다
   Bluetooth 및 장치  ButtonControl   (1889,283) 535x87
```

| | Pluiz 지금 (Vision) | UIA |
|---|---|---|
| 걸린 시간 | **평균 4.0초**(최대 6.6초) | **0.26초** |
| 비용 | 화면 1장 ≈ **1,000~1,800 토큰** | **0** |
| 좌표 | **추정** → *"추정한 위치예요"* 라벨이 필요했다 | **정확** — 컨트롤이 준 값 |
| 🚨 **켜져 있나 꺼져 있나** | **모른다.** 화면을 봐도 추정이다 | **`상태=1`** — 안다 |
| 화면이 밖으로 나가나 | **나간다** | **안 나간다** |

> 🔑 **마지막 두 줄이 기능 이상의 것이다.** «토글 상태를 안다»는 *"블루투스 켜줘"* 를
> **멱등하게** 만들고(이미 켜져 있으면 안 건드린다), «화면이 안 나간다»는 **개인정보 축**이다.

## 4. 🔴 **빈칸 60%에 경로가 있다** — UIA 패턴이 그대로 대응한다

[W-0 §2](2026-09_도구_커버리지_지도.md)에서 통째로 비었던 칸들을 UIA 패턴과 맞춰 봤다(Edge 340개 컨트롤 기준).

| UIA 패턴 | Edge에서 | 우리 빈칸 | 뜻 |
|---|---|---|---|
| **TextPattern** | **12개** | 🔴 **9~12 텍스트 선택·편집·내비게이션** | **본문·커서·선택을 읽는다** |
| **InvokePattern** | 53개 | 5 컨트롤 상호작용 | 좌표 없이 «누른다» |
| **ExpandCollapsePattern** | **97개** | 🔴 목록 펼치기 | |
| **SelectionItemPattern** | 7개 | 항목 선택 | |
| **ScrollPattern** | 2개 | 🔴 스크롤 | |
| **RangeValuePattern** | 1개 | 🔴 슬라이더 | |
| **ValuePattern** | 5개 | 입력칸 | **값을 직접 쓴다** |
| **WindowPattern** | 1개 | 창 조작 | 최대/최소/**닫기** |
| TogglePattern | 0개 | 🔴 토글 | Edge엔 없다. **설정엔 3개**(§3) |

### 📝 메모장에서 텍스트 경로를 실제로 읽었다

```
[DocumentControl] 읽기 0.8 ms
  본문 = 'Pluiz ... second line here'
  선택/커서 범위 1개
  ValuePattern = 있다 (값 직접 쓰기 가능)
```

> 🔑 **«이 문장 굵게 해줘»·«방금 쓴 단어 지워»·«세 번째 줄로 가»가 불가능한 게 아니었다.**
> **커서와 선택을 알 방법이 없었을 뿐**이고, UIA는 그걸 **0.8ms에** 준다.
>
> ⚠️ 다만 **읽는 것과 «굵게 만드는 것»은 다르다.** 서식은 앱마다 다르고
> UIA `TextPattern`은 **읽기 중심**이다. 쓰기는 `ValuePattern` · 키 입력 · 앱별 경로가 섞인다.
> **여기는 아직 «경로가 보인다»까지다.**

## 5. 🔍 `describe_screen`의 상당 부분도 대체 가능해 보인다

Edge의 `DocumentControl`에서 **페이지 본문이 그대로 읽혔다**:

```
'￼\nHome\nPluiz 시연 현황판\n￼\n￼\nComment on this artifact\nMore comment options\n'
```

*"지금 화면에 뭐 있어?"*(시연 4장면)의 **상당 부분이 토큰 0 · 0.8ms로 풀릴 수 있다.**
⚠️ **다만 그림·아이콘·레이아웃은 UIA가 못 본다.** **Vision을 대체하는 게 아니라 «먼저 시도»가 맞다.**

## 7. 남은 셋 — **AutoHotkey · MCP 소비 · PowerShell** (2026-09-17 같은 날)

### 7-1 🔌 **MCP 소비** — 🚨 **«도구를 쥐어준다»의 본체이자, 토큰 절벽의 본체**

| | |
|---|---|
| 우리 스택 | `langchain-core 1.4.2` · `langgraph 1.2.4` — **최신 계열** |
| 필요한 것 | **`langchain-mcp-adapters` 하나**(현재 **미설치**) |
| 왜 쉬운가 | MCP 도구를 **`BaseTool`로 바꿔 준다** → [`tool_registry.get_all_tools()`](../../core/tool_registry.py)에 **그대로 얹힌다.** 구조 변경이 거의 없다 |
| 생태계 | **서버 10,000개+** · SDK 월 9,700만 다운로드 · **데스크톱 자동화 서버만 25개+** |

> 🚨 **그런데 여기가 정확히 [W-0 §4 토큰 절벽](2026-09_도구_커버리지_지도.md)이 터지는 자리다.**
> **Playwright MCP 하나가 도구 22개를 들고 온다.** 우리 지금 전체가 **41개**다.
> **서버 둘만 붙여도 프롬프트가 두 배가 되고**, *"메모장 열어줘"* 한 마디가 13,000 → 25,000 토큰이 된다.
>
> 🔑 **결론: MCP는 «붙이면 되는 것»이 아니라 «도구 라우팅이 먼저인 것»이다.**
> 순서를 뒤집으면 [BL-57](../BACKLOG.md)(입력이 커지자 `out=0`)을 **자초한다.**

### 7-2 ⚙️ **PowerShell** — 값싸게 넓지만 **보안선을 넘는다**

이 PC에서 **읽기만** 돌려 봤다:

| 무엇 | 결과 |
|---|---|
| 블루투스 장치 상태 | ✅ `Get-PnpDevice -Class Bluetooth` → `OK / Intel(R) Wireless Bluetooth(R)` |
| Wi-Fi 연결·SSID | ✅ `netsh wlan show interfaces` → `State: connected · SSID: …` |
| 배터리 | ✅ 100 |
| 🎯 **설치된 앱 목록** | ✅ **227개**(레지스트리 Uninstall 키) |
| 볼륨 제어 | ⛔ `AudioDeviceCmdlets` **없음** — 별도 모듈이 필요하다 |

> 🎯 **«설치된 앱 227개»가 뜻밖의 수확이다.** 20문장 4번(*"한글 실행해 줘"*)이 **⛔ 였던 이유**가
> **앱 이름을 모르는 것**이었는데, 이 목록이 그걸 푼다. **작고 값싼 개선 후보다.**
>
> 🚨 **다만 «PowerShell 도구»를 그냥 주면 안 된다.** 그건 **LLM에게 임의 코드 실행을 주는 것**이다.
> 이 저장소가 [클릭 도구에 좌표 인자를 막은 것](../../CLAUDE.md)(절대 규칙 9)과 **같은 모양**이다 —
> **«언젠가 지어낸다»** 가 전제다. 준다면 **정해진 명령의 허용목록**으로만 준다.

### 7-3 🔧 **AutoHotkey** — 사용자가 짚은 것. **설치돼 있지 않다**

| | |
|---|---|
| 설치 여부 | ⛔ **이 PC에 없다**(`C:\Program Files\AutoHotkey` 없음) — **실측 못 했다** |
| 무엇인가 | Windows용 스크립트 자동화. 핫키 · 창 제어 · `ControlSend` · WinAPI 호출 |
| 음성 액세스와의 관계 | [분석 §6-5](2026-09_음성액세스_대조표.md) — **커스텀 명령이 AHK를 부르면 동작의 한계가 사실상 사라진다** |

> 🚨 **PowerShell과 같은 선에 걸린다.** 사용자가 **직접 쓴** AHK 스크립트를 실행하는 것과,
> **LLM이 AHK 스크립트를 지어내 실행**하는 것은 **완전히 다른 물건**이다.
> 후자는 [§6-4의 책임 구조](2026-09_음성액세스_대조표.md)를 뒤집는다 —
> **«본인이 만든 명령이라 책임이 사람에게»** 가 성립하지 않는다.
>
> 📌 **그래서 AHK는 «우리가 쥘 도구»보다 «경쟁 지형»으로 보는 게 맞다.** [W-2·W-3](2026-09_경쟁_에이전트_지형.md) 참조.
