## 1. 무엇을 «오프라인에서 된다»로 셌나

[BL-46](../BACKLOG.md) 이후 오프라인 턴은 **LLM을 아예 안 부른다.**
그러니 오프라인에서 되는 것은 정확히 **`fast_path`가 잡는 것**뿐이다.

| 단계 | 무엇 | 센다? |
|---|---|---|
| ⛔ 게이트 | 복합·부정·다중앱이면 캐시를 건너뛴다(BL-02·BL-27·BL-50) | ✗ |
| ✅ **캐시** | `(entity, action)` 인텐트 + 유사도 | **✓** |
| ⛔ BL-15 | 캐시가 문장의 **일부만** 이해했으면 포기 | ✗ |
| ✅ **라우터** | 파라미터형 정규식 9종 | **✓** |
| 🟡 제안 | *"혹시 이 말씀인가요?"*(M5 §5-2) | **따로 센다** |

> 🔑 **«제안»을 «된다»에 넣지 않았다.** 되묻는 것과 해 주는 것은 다르다.
> 넣으면 숫자가 올라가지만 그건 **우리에게 유리한 쪽으로 세는 것**이다.

### 🚨 측정 도구는 **아무것도 실행하지 않는다**

`resolve_fast_path`는 히트하면 **도구를 진짜로 돌린다.** 120문장을 그대로 먹이면
측정이 아니라 난장판이 된다. 그래서 판정 함수만 부르고 `execute_sync`는 **안 부른다.**
대신 «판정 경로가 실물과 같은가»가 위험해지므로, 게이트는 **`core.fast_path`에서
그대로 import** 하고 라우터는 **모듈 상수인 정규식**을 쓴다 — 복제하지 않는다.

## 2. 고정 20문장 — **10 / 20 (50.0%)**

> 🚨 **유리하게 고르지 않았다.** 캐시 시드에서 뽑으면 100%가 나온다 — 그건 재는 게
> 아니라 베끼는 것이다. **여섯 갈래를 먼저 정하고** 갈래마다 채웠고,
> 안 될 것이 뻔한 것(날씨·잡담)도 그대로 넣었다. 대부분 **실제 로그 발화**다.

| 갈래 | 결과 | |
|---|---|---|
| 앱 제어 | **3/4** | ⛔ *"한글 실행해 줘"* |
| 시스템 | **2/4** | ⛔ *"소리 꺼줘"* · 🟡 *"화면 밝기 좀 올려줘"*(제안만, cos=0.63) |
| 창 | **2/2** | 라우터 정규식이 다 잡는다 |
| 정보(로컬) | **3/3** | 시각 · 배터리 · 실행 중인 앱 |
| 🚫 온라인 | **0/3** | **정상이다** — 날씨·웹검색은 망이 있어야 한다 |
| 🚫 복합·지시대명사·잡담·맥락 | **0/4** | **정상이다** — 게이트가 일부러 막는다 |

### 🔑 그래서 숫자를 **두 가지로** 말해야 한다

| 무엇을 분모로 | 값 | 무엇을 말하나 |
|---|---|---|
| 20문장 전체 | **50.0%** | «오프라인에서 절반은 된다» — 정직하지만 **분모에 안 될 것이 섞여 있다** |
| **로컬 명령 13개만** | **76.9%** | «망이 필요 없는 명령은 4개 중 3개가 된다» — 🔑 **차별점 주장은 이쪽이다** |

⚠️ **둘 다 적어야 한다.** 76.9%만 말하면 분모를 골라낸 것이고, 50%만 말하면
«안 되는 게 정상인 것»까지 실패로 센 것이다.

## 4. 🚨 재다가 찾은 결함 — **«잡히는데 망이 필요한» 명령**

첫 판에서 *"유튜브에서 아이유 노래 틀어줘"* 가 **라우터 히트 → ✅ 된다**로 집계됐다.
그런데 `youtube_search`는 **브라우저를 열고 인터넷을 탄다.**

**오프라인에서 이 명령이 어떻게 흘러가는지 코드로 따라가 보면**:

1. `fast_path` → 라우터 정규식 `_ROUTER_YT` 히트 (**오프라인 판정보다 앞이다**)
2. `youtube_search` → API 호출 실패 → `except` → **검색 페이지로 폴백**
3. `_open_with_browser(url)` → `os.startfile` 성공(브라우저는 뜬다. 페이지는 오류다)
4. → **`"✓ 유튜브에서 '아이유 노래' 검색했어요"`**

**브라우저에는 «인터넷 없음» 오류 페이지가 떠 있는데 Pluiz는 성공했다고 말한다.**

> 🔑 이건 [전수 감사 **G-17**](2026-09_안전에러_전수감사.md)(브라우저 열기 폴백이
> 실패해도 조용하다)이 **오프라인에서 더 나쁜 얼굴로 나타난 것**이다.
> 감사 때는 «드물다»고 봤는데, **오프라인에서는 항상 그렇게 된다.**
>
> ⚠️ 그리고 **[BL-46](../BACKLOG.md)의 오프라인 단락이 이걸 못 막는다** —
> BL-46은 «오프라인이면 **LLM을** 안 부른다»이고, 라우터는 **그보다 앞**에 있다.

**해당 갈래**: `youtube_search` · `map_search`(지도 2종) · `web_search` · `open_url` · 날씨.
📌 측정 도구에는 **`🌐 잡히지만 망이 필요` 칸을 따로 만들었다.** «된다»에 넣지 않는다.

| ② | *"소리 꺼줘"* 가 미스 | 엔티티는 volume 인데 동작이 `close` 로 잡혀 **없는 조합** |
| ③ | *"한글 실행해 줘"* 가 미스 | 앱 사전에 없었다 |

**①이 제일 크고, 표를 넓히는 일이 아니었다.** `ACTION_PATTERNS` 의 트리거는
「밝기 올」처럼 **두 어절에 걸친 것**이 많은데 매칭은 공백만 지운 문자열에서 한다.
그래서 사이에 「좀」이 끼면 `"화면밝기좀올려줘"` 에 「밝기올」이 **없다.**

📌 **이미 알고 있던 결함이다.** `has_uncovered_command` 주석에 실측 오탐으로
*"볼륨 좀 올려줘"(「볼륨 올」 트리거가 '좀' 때문에 안 걸림)* 가 적혀 있었다.
그때는 **게이트가 안 막도록** 처리했을 뿐 **못 맞히는 것 자체는 남아 있었다** —
증상을 비껴간 자리에 원인이 3주 더 살아 있었다.

### 🔑 고치면서 나온 것 — 폴백에도 **순서**가 필요했다

「원문으로 먼저 훑고 실패하면 삽입어를 빼고 다시」로 짰더니 *"소리 좀 꺼줘"* 가
**(volume, close)** 로 갔다. 원문에서 아래쪽의 `close`(「꺼줘」)가 **먼저 걸려**
1차가 «성공»해 버리니 2차가 돌지 않는다. 그래서 **둘 다 훑고 표의 순서로 고른다** —
`ACTION_PATTERNS` 의 순서가 이 파일의 정확성 장치라는 것(「밝기가 볼륨보다 먼저」)과
같은 이야기다.

### 🔑 ③이 남긴 불변식 — **사전은 짝이 맞아야 한다**

`APP_ENTITIES`(캐시)에만 넣고 `APP_ALIASES`(실행)에 안 넣으면 **캐시는 히트하는데
실행이 실패한다.** 코드 주석이 경고만 하고 있던 것을 `tests/test_offline_boost.py` ⑤가
**검사로** 바꿨다 — 다음에 앱을 늘릴 때 한쪽만 넣으면 거기서 깨진다.

📌 「한글」은 **이 PC에 실제로 있는 것을 확인하고** 넣었다(한컴오피스 2024).
경로는 버전을 고정하지 않고 glob 으로 뒀다 — 고정하면 업그레이드한 날부터
조용히 «못 찾음»이 된다.

### 🆕 같은 날 실기가 둘을 더 찾았다 — **음소거에 방향이 없었다**

셋을 실기로 확인하는 자리에서 **되돌릴 방법이 없다**는 것이 드러났다.

| | 무엇 | 로그 |
|---|---|---|
| ① | *"소리 다시 켜 줘"* 가 **캐시에도 LLM 에도 갈 곳이 없었다** | `실행=없음 · 사유=못함` |
| | 🚨 그때 **모델은 도구 없이 «✓» 로 답하려 했다** — BL-61 그물이 막았다 | `[BL-61] 도구 0개인데 «✓»` |
| ② | `mute_toggle` 이 **눌렀는데 상태가 안 바뀌었다** | `[음소거] 눌렀는데 그대로다 (1)` |

뿌리가 하나였다 — **도구가 `mute_toggle` 하나뿐이라 「꺼/켜/해제」가 전부 같은 토글로
무너진다.** 이미 켜져 있을 때 *"소리 켜 줘"* 는 **소리를 끈다**. 정직하게
*"✓ 음소거했어요"* 라고 말해도 **시킨 것의 반대**다.

②는 이 도구만 `keybd_event` 로 키를 **주입**하고 곧바로 상태를 읽어서다 —
키 주입은 비동기라 읽기가 앞지른다. 볼륨·밝기는 COM 으로 직접 설정해 이 문제가 없었다.

**그래서 도구를 `mute` · `unmute` 둘로 갈랐다**(46 → 47). 방향이 있고, 멱등이고
(같은 말을 두 번 해도 같다), COM 으로 직접 설정해 경합이 없다.
상태를 못 읽는 PC 에서는 **방향을 보장할 수 없다고 말한다** — 지어내지 않는다.

### 🔑 그리고 씨앗이 조용히 낡아 있었다

도구 이름을 바꾸면서 `_seed()` 가 «없으면 넣는다»만 하는 것이 드러났다.
고치고 돌리니 **44개가 갱신됐다** — 그중 대부분은 도구가 아니라 **말투**였다.
**2026-09-23 의 말투 통일(2-2 ⓐ)이 디스크에 있는 캐시 씨앗에는 도달하지 않고 있었다.**
코드는 해요체인데 저장된 `response_template` 은 «…했습니다» 그대로였고,
그 문자열은 **도구가 결과를 못 낼 때 사용자에게 나간다**.

🔑 **코드와 저장된 데이터가 같은 사실을 두 벌로 갖고 있으면 한쪽만 갱신된다** —
이 저장소가 문서에 대해 반복해 적어 온 것과 같은 모양이고, 이번엔 **런타임 데이터**였다.
