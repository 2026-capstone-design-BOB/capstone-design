## 1. W-2 — 컴퓨터 사용 AI 에이전트 (**우리와 같은 부류**)

### 1-1 📊 OSWorld 점수 — **이 분야 전체가 아직 못 한다**

| 무엇 | OSWorld |
|---|---|
| 🧑 **사람** | **72%** |
| OpenAI Operator (CUA) | **38.1%** |
| UI-TARS-72B (ByteDance · 오픈소스) | **24.6%** |
| Anthropic Computer Use | 22.0% |
| GPT-4o 베이스라인 | 12.2% |

> 🔑 **최고가 38%다.** *"화면을 보고 사람처럼 클릭한다"* 는 **아직 절반도 못 간다.**
> **이게 우리 설계를 옹호한다** — Pluiz는 **아는 명령을 네이티브 API로 바로 부르고**
> 그 경로에서 **LLM 호출 0회 · 화면 0장**이다([동향점검 §③](2026-09_동향점검.md)).
> **«범용 화면 조작»에 올인하지 않은 것이 지금 시점에선 합리적이다.**

### 1-2 🚨 접근성 트리에 대한 **반대 증거** — W-1을 그대로 두면 안 된다

- **UI-TARS**: 접근성 트리도 DOM도 안 쓴다. **스크린샷만** 받아 좌표를 직접 낸다
- **Agent S**: 반대로 **접근성 트리를 쓴다**
- 연구 쪽 지적: *"트리의 긴 텍스트를 통째로 넣으면 **비효율 · 환각 · 트리에 빠진 정보로 인한 편향**이 생긴다"*

| | 트리(UIA) | 픽셀(Vision) |
|---|---|---|
| 아는 컨트롤 | 🟢 **정확 · 빠름 · 공짜** (W-1 실측) | 🟡 느리고 추정 |
| 트리에 **없는 것**(캔버스·게임·커스텀 UI) | 🔴 **아예 안 보인다** | 🟢 보인다 |
| 큰 앱 | 🔴 **텍스트가 길어져 환각·편향** | 🟡 화면 1장으로 고정 |
| 비용 | 0 | 1,000~1,800 토큰 |

> 🔑 **둘은 대체재가 아니라 보완재다.** 우리 [W-1 실측](2026-09_외부도구_후보.md)에서
> Edge 78개 · 설정 74개는 **넣을 만한 크기**였지만, **큰 앱은 수천 개가 될 수 있다.**
> **후보 A에는 «상한»이 반드시 붙어야 한다.**

### 1-3 🪦 그리고 **경쟁 제품이 죽고 있다**

| | |
|---|---|
| **OpenAI Operator** | **2025-08-31 종료.** ChatGPT agent가 흡수 |
| **ChatGPT agent** | **2026년 8월 초 예고 없이 제거** |
| Open Interpreter | 2026년 1월 리서치 프리뷰 → 유료 플랜에서 macOS·Windows |

> ⚠️ **이걸 «우리가 이겼다»로 읽으면 안 된다.** 오히려 **«이 문제가 어렵다»는 증거**다.
> 다만 발표에서 쓸 수 있는 정직한 문장은 있다 —
> *"범용 화면 조작은 대기업도 접었다 폈다 합니다. 저희는 **아는 일을 확실히 하는 쪽**을 골랐습니다."*

## 2. W-3 — 음성 제어 제품

### 2-1 🎙️ **Talon Voice** — 커스텀 명령의 끝판. **우리가 배울 것이 있다**

| | |
|---|---|
| 무엇 | 음성 · 시선 추적 · **소리(noises)** 로 PC 제어. macOS · Linux(X11) · **Windows** |
| 커스텀 | **`.talon` 파일 + Python 스크립트.** 사용자가 문법을 통째로 정의한다 |
| 생태계 | `talonhub/community` — **커뮤니티가 유지하는 명령 집합** |
| 접근성 | 시스템 접근성 API에 붙는다 · NVDA 연동본도 있다 |
| 겨냥 | **핸즈프리 코딩** — 개발자 |

> 🔑 **배울 것**: 음성 액세스의 커스텀 명령이 «동작 8개 묶기»라면,
> **Talon은 «문법 자체를 사용자가 정의»한다.** 그리고 **커뮤니티가 명령 집합을 공유**한다.
> ⚠️ **대신 진입 장벽이 우리와 정반대다** — 스크립트를 쓸 줄 알아야 한다.
> **우리 주장(«만들지 않아도 된다»)의 대척점**이라 **비교축으로 쓰기 좋다.**

### 2-2 다른 것들 — **수확체감 구간이라 얕게 본다**

| | 한 줄 |
|---|---|
| **Dragon** | 받아쓰기 정확도 상용 최강 계열. **명령보다 «받아쓰기» 제품** |
| **macOS Voice Control** | 음성 액세스와 같은 계열(접근성 · 숫자 오버레이 · 격자) |

> ⚠️ **둘 다 실행해 보지 않았다.** 문서 판정이고, [«문서 먼저, 실측은 사용자»] 원칙대로
> **필요해지면 그때 잰다.** 지금은 판단을 바꿀 만한 축이 안 보인다.

## 3. 🗺️ 그래서 **우리 자리는 어디인가** — 축이 둘이다

```
                     범용성 (아무 화면이나)
                              ▲
        UI-TARS · Operator    │    (아무도 없음)
        Claude Computer Use   │
        ─────────────────────┼─────────────────────▶ 확실성
                              │                      (되면 확실히 된다)
        (아무도 없음)          │   Pluiz · 음성 액세스 · Talon
                              │
```

| | 범용성 | 확실성 | 한국어 자연어 | 안전(HITL) |
|---|---|---|---|---|
| **컴퓨터 사용 에이전트** | 🟢 높다 | 🔴 **38%** | 🟡 모델 나름 | 🟡 격리 VM 권장 |
| **음성 액세스** | 🟡 UI 전반 | 🟢 **높다** | 🔴 **정해진 문법** | ⚪ 필요 없다(안전한 동작만) |
| **Talon** | 🟡 | 🟢 높다 | 🔴 **직접 만들어야** | ⚪ 사용자 책임 |
| 🎯 **Pluiz** | 🟡 **도구 41개만큼** | 🟢 **아는 건 확실** | 🟢 **자연어** | 🟢 **승인 구조** |

> 🔑 **우리 빈칸은 «범용성»이고, W-1의 UIA가 바로 그 칸을 넓힌다.**
> **그런데 §1-2가 경고한다** — 트리에 없는 것은 **여전히 Vision이 필요하다.**
> **«둘 다 쥐고 싼 것부터 시도»가 이 지형이 가리키는 설계다.**
