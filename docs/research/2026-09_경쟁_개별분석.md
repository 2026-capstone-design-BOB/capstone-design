# 1. 🤖 Anthropic **Claude Computer use**

### 한 줄
**API로 «화면을 보고 클릭·타이핑하는 능력»을 파는 것.** 제품이 아니라 **부품**이다.

### 어떻게 만들었나 — **도구 3개 조합**

| 도구 | 하는 일 |
|---|---|
| `computer` | 스크린샷 · 마우스 · 키보드 |
| `text_editor` | 파일 보기·만들기·바꾸기 — **`view` `create` `str_replace` `insert` `undo_edit` 5개** |
| `bash` | **셸 명령 실행**(세션이 유지된다) |

### 숫자

| | |
|---|---|
| 화면 입력 상한 | **Opus 4.7+ 긴 변 2576px · 시각 토큰 4784** (이전 모델은 1568px) |
| 화면 1장 비용 | 약 **1,000~1,800 토큰** |
| 모델 가격(2026-09) | Opus 4.8 **$5 / $25** · Sonnet 5 **$2 / $10** · Haiku 4.5 **$1 / $5** (1M 토큰) |
| 절약 | 배치 **50% 할인** · 프롬프트 캐싱 **입력 90% 절감** |
| OSWorld | **22.0%** (⚠️ 조건 다름 — [지형도 §3](2026-09_경쟁_에이전트_지형.md)) |

### 강점 / 약점

| 🟢 강점 | 🔴 약점 (**공식 문서가 스스로 밝힌 것**) |
|---|---|
| 어떤 앱이든 화면만 있으면 된다 | **드롭다운·스크롤바를 마우스로 다루기 어렵다** → **키보드 단축키 권장** |
| 파일 편집·셸이 한 세트 | **좌표 스케일 불일치 · 축소로 작은 글자 손실 · 낮은 해상도** |
| 생태계·문서가 두껍다 | **프롬프트 인젝션** 경고 — 화면 속 글자가 지시를 덮어쓸 수 있다 |
| | **격리 VM/컨테이너 권장 · 자격증명 제공 금지** |

### 🎯 우리가 가져올 것

1. **`text_editor`의 5개 구성**(`view`/`create`/`str_replace`/`insert`/`undo_edit`) —
   우리 [텍스트 편집 표면 후보](2026-09_개편_후보.md)의 **설계 참고서**다. **바퀴를 다시 안 만들어도 된다**
2. **화면 자동 축소 정책** — 우리도 화면을 줄여 보내는데, **상한을 근거 있게 정할 수 있다**
3. **«중대한 행동에 사람 승인»** — 🔑 **우리가 이미 하고 있다.** *"업계 권고와 같은 구조"* 라고 말할 수 있다

### ⛔ 안 가져올 것

**`bash` 도구.** LLM에게 **임의 셸 실행**을 주는 것이고 [우리 금지선](2026-09_개편_후보.md)이다.
Anthropic은 **격리 VM**을 전제로 그걸 준다. **우리는 사용자 데스크톱에서 직접 돈다** — 전제가 다르다.

### 🎤 질문받으면

> **Q. "그냥 Claude Computer use 쓰면 되지 않나요?"**
> *"그건 **부품이고 저희와 전제가 다릅니다.** Anthropic 문서가 **격리 VM에서 쓰라**고 권고합니다.
> 저희는 **사용자의 실제 데스크톱**에서 돌아서, 같은 안전을 **격리가 아니라 승인 구조**로 얻습니다.
> 그리고 **매 단계 화면을 보내지 않습니다** — 아는 명령은 Windows API로 바로 부르고
> 그 경로에서 **모델 호출 0회 · 화면 0장**입니다."*
>
> **Q. "성능은 어느 쪽이 낫나요?"**
> *"**범용성은 저쪽이 압도적입니다.** 저희는 **아는 범위 안에서 확실한 쪽**을 골랐습니다.
> 다만 공개 벤치마크로 저희를 잰 적은 없어서 **숫자로 비교하지는 않겠습니다.**"*

# 2. 🪟 Microsoft **Copilot Actions** (Windows 11)

### 한 줄
**Windows가 직접 만드는 «화면 조작 에이전트».** 🔴 **우리 서사의 시한이다.**

### 어떻게 만들었나 — **«격리»로 안전을 얻는다**

| | |
|---|---|
| 방식 | **비전 + 추론**으로 사람처럼 클릭·타이핑·스크롤 |
| 🔑 **에이전트 워크스페이스** | 에이전트마다 **전용 저권한 Windows 계정** + **격리된 데스크톱 세션**. 사용자가 계속 일하는 동안 **따로** 돈다 |
| 파일 접근 | **문서·다운로드·바탕화면·사진** 등 **알려진 폴더로 제한.** 그 밖은 **사용자 승인 필요** |
| 🎯 **투명성 대시보드** | 에이전트가 **한 모든 행동을 사용자가 보고**, **권한을 한 번에 취소**할 수 있다 |
| 상태 | 🟡 **프리뷰**(Insider · 빌드 **26100.7344+** · **기본 꺼짐**) |
| 정식 출시 | **2027년으로 본다** |

### 강점 / 약점

| 🟢 | 🔴 |
|---|---|
| **OS가 직접 만든다** — 권한·계정 수준에서 격리 가능 | **아직 프리뷰이고 기본 꺼짐** |
| 투명성 대시보드가 **제품 기능**이다 | **Microsoft 스스로 보안 경고**를 냈다 |
| 클라우드·계정 생태계와 붙는다 | **격리 세션이라 «내 화면»을 그대로 돕는 건 아니다** |

### 🎯 우리가 가져올 것

1. 🔴 **투명성 대시보드** — **우리에게 정확히 이 구멍이 있다.**
   2차 리허설에서 *"지금까지 한 거 뭐 했는지 정리해 줄래"* 가 «못함»으로 끝났고([BL-56](../BACKLOG.md)),
   그때 적어 둔 문장이 *"**재료는 이미 다 있는데 그걸 보는 자리가 없다**"* 였다.
   **Microsoft는 그걸 제품의 핵심 기능으로 만들었다.** 🔑 **이건 베껴야 한다.**
2. **최소 권한 · 알려진 폴더로 제한** — 우리 [보호 경로 검사](../../tools/filesystem.py)와 같은 방향

### ⛔ 안 가져올 것

**격리 계정 · 별도 데스크톱 세션.** 우리는 **사용자가 보는 화면에서 같이 일하는 것**이 정체성이다
(그래서 «화면을 짚어 준다»가 가능하다). **격리하면 그게 사라진다.**

### 🎤 질문받으면

> **Q. "Windows가 곧 기본으로 넣을 텐데요?"**
> *"맞습니다. **2027년 정식 출시로 보고 있습니다.** 저희 조사 문서에 **시한**으로 적어 뒀습니다.
> 다만 셋이 다릅니다 — ① **저쪽은 격리된 별도 세션**이고 저희는 **사용자 화면에서 같이** 합니다
> ② **한국어 자연어 명령**은 아직 저쪽 축이 아닙니다
> ③ **저희는 인터넷 없이 절반이 돕니다.**
> 그리고 **10월 말에 다시 조사해서 정식 출시 여부를 확인하는 일정**을 잡아 뒀습니다."*
>
> **Q. "그럼 이 프로젝트는 곧 의미가 없어지나요?"**
> *"«Windows가 하면 끝»이라고 보지 않습니다. **접근성 음성 제어(음성 액세스)가 이미 있는데도
> 볼륨 하나 못 바꿉니다.** 큰 회사가 만든다고 **모든 칸이 채워지지는 않습니다.**
> 저희가 고른 칸은 **«한국어 자연어 + 확실성 + 승인»** 이고, 조사 범위 안에서 **비어 있었습니다.**"*

# 3. 🥇 **Agent S3** (Simular)

### 한 줄
**OSWorld에서 사람을 넘은 첫 컴퓨터 사용 에이전트** (**72.60%**, 사람 ≈72%).

### 어떻게 만들었나 — **«여러 번 해보고 제일 나은 걸 고른다»**

| | |
|---|---|
| 🔑 **bBoN**(Behavior Best-of-N) | 한 번이 아니라 **여러 갈래로 실행**(rollout)하고, 각 갈래를 **«무슨 일이 있었나» 서사로 요약**한 뒤 **심판이 최선을 고른다** |
| 구조 변화 | S2의 **관리자–작업자 계층을 버리고** 평평한 구조(작업자만)로 → **빨라졌다** |
| 하이브리드 | 매 단계 **«GUI를 조작할까, 코딩 에이전트를 부를까»** 를 고른다(대량 작업·파일 변환은 코드로) |
| 화면 | **접근성 트리 + 화면** 둘 다 |

### 강점 / 약점

| 🟢 | 🔴 |
|---|---|
| **사람 수준 성능**(보고 기준) | 🚨 **N배 비용.** 여러 갈래를 다 돌린다 |
| 계층을 없애 **단순·고속** | 자기 보고 벤치마크 |
| **«GUI냐 코드냐»를 상황별로** | 개인 PC 상시 사용에는 무겁다 |

### 🎯 우리가 가져올 것

**«GUI냐 코드냐»를 매 단계 고르는 구조** — 🔑 **우리 [계획 노드](../design/M3_계획수립노드.md)와 같은 모양**이고,
[도구 라우팅 후보](2026-09_개편_후보.md)의 **상위 개념**이다. *"같은 문제를 1등도 같은 방식으로 푼다"* 고 말할 수 있다.

### ⛔ 안 가져올 것

**bBoN.** **여러 번 돌려서 고르는 건 비용이 N배**다.
우리는 **LLM 호출 1회도 아끼려고 캐시를 만든 프로젝트**다([캐시 절감액](2026-09_캐시_절감액.md) — 히트율 22.4%).
**설계 철학이 정반대다.** 벤치마크를 겨냥하면 맞는 선택이고, **매일 쓰는 PC 비서에는 틀린 선택**이다.

### 🎤 질문받으면

> **Q. "이미 사람 수준인 에이전트가 있는데요?"**
> *"**벤치마크 조건을 봐야 합니다.** ① 그 72%는 **OSWorld**이고, **Windows 전용 벤치마크에서는
> 최고가 아직 20%대**입니다(사람 74.5%). ② 그 성능은 **한 과제를 여러 번 돌려 제일 나은 걸 고르는 방식**으로
> 얻습니다 — **비용이 배로 듭니다.**
> 저희는 **반대 방향**입니다. 같은 명령 두 번째는 **모델을 아예 안 부릅니다**(실사용 22.4%가 그렇게 끝났습니다)."*

# 4. 🧠 **UI-TARS / UI-TARS-2** (ByteDance)

### 한 줄
**«화면만 보고 움직이는 전용 모델»을 통째로 학습시킨 것.** 오픈소스 GUI 에이전트 중 최대 규모.

### 어떻게 만들었나 — **끝에서 끝까지 한 모델**

| | |
|---|---|
| 입력 | 🚨 **스크린샷만.** 접근성 트리도 DOM도 **안 쓴다** |
| 출력 | **절대 좌표로 직접 행동** |
| 학습 | **대규모 강화학습**(멀티턴) + **데이터 플라이휠** |
| 🔑 **메모리 구조** | **작업 기억**(직전 상호작용 · 반응 제어) + **일화 기억**(장기 지식 압축 · 긴 과제에서 복구·탐색) |
| 환경 | GUI + **파일시스템·터미널**을 섞은 하이브리드 |

### 강점 / 약점

| 🟢 | 🔴 |
|---|---|
| **트리가 없는 화면도 본다**(게임·캔버스) | **전용 모델을 학습해야 한다** — 우리 규모 밖 |
| 좌표를 직접 낸다 — 중간 부품이 없다 | 픽셀만이라 **작은 글자·저해상도에 약한** 구조적 한계 |
| 오픈소스 | OSWorld 24.6%(조건 다름) — **Agent S3보다 낮다** |

### 🎯 우리가 가져올 것

🔑 **계층적 메모리(작업 기억 / 일화 기억)** — **우리 히스토리 관리는 `trim_messages` 하나뿐**이다.
*"방금 뭐 했는지"* 에 못 답하는 것([BL-56](../BACKLOG.md))과 **같은 뿌리**다.
**«긴 과제를 요약해 들고 다니는 자리»** 가 우리에겐 없다.

### ⛔ 안 가져올 것

**전용 모델 학습.** 데이터·GPU 규모가 다르다.
⚠️ 다만 **웨이크워드는 우리가 실제로 학습한다**([M7](../design/M7_웨이크워드_재구축.md)) — **거기까지가 우리 규모**다.

### 🎤 질문받으면

> **Q. "접근성 API보다 화면을 직접 보는 게 낫지 않나요? UI-TARS는 그렇게 하던데요."**
> *"**둘 다 근거가 있습니다.** UI-TARS는 픽셀만 쓰고, **지금 1등인 Agent S3와 Windows-MCP는 접근성 트리를 씁니다.**
> 트리는 **정확하고 공짜지만 게임·캔버스처럼 비어 있는 앱**이 있고,
> 픽셀은 **뭐든 보지만 느리고 추정**입니다.
> 저희가 실측해 보니 **같은 작업이 4.0초 → 0.26초, 토큰 0**이었습니다.
> 그래서 **트리를 먼저 보고, 없으면 화면으로 떨어지는** 쪽으로 설계했습니다."*

# 5. 🎯 **Windows-MCP** (오픈소스)

### 한 줄
🚨 **우리가 하려는 걸 이미 해놓은 것.** Windows 접근성 기반 도구 모음을 **MCP 서버**로 판다.

### 무엇을 주나 — **도구 19개**

| 묶음 | 도구 |
|---|---|
| 조작 | `Click` `Type` `Scroll` `Drag` `Move` |
| 키보드 | `Shortcut`(Ctrl+C·Alt+Tab 등) `Key` `Wait` |
| 🔑 **인식** | **`State`** — **활성 앱 + 조작 가능한 UI 요소를 한 번에** · `Screenshot` |
| 앱·시스템 | `Launch`(시작 메뉴에서 실행) · 🚨 **`Shell`(PowerShell)** |
| 기타 | `Clipboard` `Scrape` `Process` `Registry` `FileSystem` |

| | |
|---|---|
| 특징 | **비전 모델이 필요 없다** — 접근성 트리로 인식 |
| 설치 | `uvx` **한 줄** |
| 성숙도 | 공식 MCP 레지스트리 · **Claude Desktop 확장 설치 200만+** · Windows 7~11 |
| 속도 | **클릭-투-클릭 200~500ms** |

### 🎯 우리가 가져올 것

1. 🔑 **`State` 도구의 개념** — *"지금 화면에서 조작할 수 있는 것 목록"* 을 **한 번에** 주는 도구.
   우리 `describe_screen`(4.0초 · 화면 1장)보다 **싸고 정확하다.** [후보 A](2026-09_개편_후보.md)가 이것의 축소판이다
2. **«비전 없이도 된다»는 증명** — 200만 설치가 **우리 방향이 착각이 아님**을 보인다

### ⛔ 안 가져올 것 — **통째로는 못 쓴다**

| | 왜 |
|---|---|
| ⛔ **`Shell`(PowerShell)** · **`Registry`** | LLM에게 **임의 코드 실행 · 레지스트리 편집**을 주는 것. [우리 금지선](2026-09_개편_후보.md) |
| 🚨 **도구 19개를 통째로** | 우리 41개 + 19개 = **60개.** *"30개 넘으면 모델이 못 고른다"* 의 **두 배**다 → **도구 라우팅이 먼저** |

### 🎤 질문받으면

> **Q. "이미 있는 오픈소스를 쓰면 되지 왜 직접 만드나요?"**
> *"**일부는 실제로 가져올 계획입니다.** 다만 통째로는 못 씁니다 — 이유가 둘입니다.
> ① 그 서버는 **PowerShell과 레지스트리까지 열어 줍니다.** 저희는 **모델에게 임의 코드 실행을 주지 않는 것**을
> 설계 원칙으로 두고 있어서 그대로는 못 씁니다.
> ② **도구가 19개 더 늘면 프롬프트가 터집니다** — 지금도 한 마디에 13,000 토큰이고,
> 연구에서도 **«도구 30개를 넘으면 모델이 제대로 못 고른다»** 고 보고됩니다.
> 그래서 **필요한 도구만 골라 넣는 구조를 먼저** 만들고 나서 붙이는 순서로 잡았습니다."*

# 6. ♿ **Windows 음성 액세스** — 🔬 **직접 써 본 유일한 것**

### 한 줄
**목소리로 마우스·키보드를 대신하는 접근성 기능.** 그 일은 **우리보다 잘한다.**

> 📄 **전체 분석은 [별도 문서](2026-09_음성액세스_대조표.md)에 있다.** 여기는 요약이다.

| | |
|---|---|
| 🔬 **실측** | *"메모장 열어"* 는 **안 열린다.** `<앱이름> 열기` 여야 한다 — **토씨 하나 안 틀려야 한다** |
| 한국어 | ✅ 지원(빌드 26200.8973+) · 이 PC에서 **선택돼 있음** 확인 |
| 규모 | **명령의 60%가 텍스트 선택·편집·서식·내비게이션** |
| 커스텀 | 동작 **8개 이상**을 한 명령에 · 그룹화 — ⚠️ **영어 모드 전용** |
| 오프라인 | ✅ **설계 전제다** |
| ⛔ 없는 것 | 시스템 설정(볼륨·밝기) · 시간·배터리 질문 · 날씨·잡담 · 파일 열기/지우기 · **즉석 복합 명령** |

### 🎯 가져올 것 / ⛔ 안 가져올 것

🎯 **어휘에 추가**(발음 어려운 단어를 사용자가 등록) — 우리 *"에이점 티엑스티"* 문제의 다른 해법
🎯 **동작하기 전 대기 시간을 사용자가 고르게** (기본 0.5초) — 우리는 **1.2초 고정**이다
⛔ **정해진 문법** — 🔑 **이게 우리가 반대로 가는 지점이다**

### 🎤 질문받으면

> **Q. "Windows에 이미 음성 제어가 있잖아요?"**
> *"있고, **직접 써 봤습니다.** 그런데 **«메모장 열어»라고 하면 안 열립니다** — «메모장 열기»여야 합니다.
> **토씨 하나 안 틀려야 하는 구조**입니다. 그리고 **볼륨·밝기 같은 시스템 설정 명령이 아예 없고,
> «지금 몇 시야» 같은 질문에 답하지 않습니다.**
> **목소리로 마우스와 키보드를 대신하는 도구**지, **시켜서 일을 끝내는 대리인**이 아닙니다."*

# 7. 🎙️ **Talon Voice**

### 한 줄
**문법 자체를 사용자가 정의하는 음성 제어.** 핸즈프리 코딩의 사실상 표준.

| | |
|---|---|
| 방식 | **`.talon` 파일 + Python 스크립트** |
| 입력 | 음성 · **시선 추적** · 🎯 **소리(noise)** — 혀 차기·쉿 소리 같은 것도 입력이다 |
| 생태계 | `talonhub/community` — **커뮤니티가 함께 유지하는 명령집** |
| 접근성 | 시스템 접근성 API 연동 · NVDA 연동본 존재 |
| 한국어 | ⛔ |
| 위치 | Serenade 개발 정체 · Dragon 비권장 → **음성 코딩은 Talon으로 수렴** |

### 🎯 우리가 가져올 것

1. 🎯 **소리(noise) 입력** — *"응/아니"* 대신 **짧은 소리로 승인**. 🔑 **우리 승인 절차가 STT에 깨진 적이 있다**([BL-53](../BACKLOG.md)) — 소리는 **오인식이 없다**
2. **커뮤니티 명령집** 개념 — 우리 [내보내기/가져오기](../design/)가 그 씨앗이다

### ⛔ 안 가져올 것

**사용자가 문법을 정의하는 모델.** 🔑 **우리 주장의 정반대**다 — *"만들지 않아도 그 자리에서 말하면 된다."*

### 🎤 질문받으면

> **Q. "Talon처럼 사용자가 명령을 만들게 하면 되지 않나요?"**
> *"그 방향은 **매우 강력한데 전제가 다릅니다.** Talon은 **스크립트를 쓸 줄 아는 사람**을 위한 도구입니다.
> 저희가 겨냥한 건 **만들지 않아도 되는 쪽**입니다.
> 다만 **소리로 승인하는 입력 방식**은 저희도 가져올 만하다고 보고 후보에 적어 뒀습니다 —
> 저희 승인 절차가 **음성 인식 오류에 깨진 적**이 있어서요."*
