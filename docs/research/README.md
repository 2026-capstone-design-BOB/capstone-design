## 왜 이 폴더가 있나

AI Agent는 개념이 빨리 바뀐다. 이 프로젝트가 기준으로 삼은 강의 정리도 **2026-07 기준**이고,
비교 대상(computer use · Copilot Actions)은 공식 문서가 **분기마다 바뀐다.**

그런데 *"동향을 추적했다"* 는 말은 **기록이 없으면 증명되지 않는다.**
그래서 추적을 의지가 아니라 **구조**로 고정한다 — 항목을 고정하고, 주기를 고정하고,
**안 한 것도 왜 안 했는지 적는다.**

> 이 프로젝트가 반복해서 배운 것과 같은 모양이다:
> **프롬프트(의지)는 확률을 올릴 뿐이고 보장하는 건 구조다.**

## 고정 항목 5개 — 매달 같은 것을 본다

항목이 고정돼야 **변화가 눈에 띈다.** 이번 달에만 궁금한 것을 추가하지 않는다.

| # | 항목 | 무엇을 보나 | 자동화 |
|---|---|---|---|
| ① | **모델 · API** | 단가 · 컨텍스트 길이 · **도구 호출 신뢰도** | 수동 (공식 가격표) |
| ② | **프레임워크** | `requirements.lock.txt` 고정 버전 vs 최신 · 릴리스 노트 | ✅ [`scripts/check_deps_drift.py`](../../scripts/check_deps_drift.py) |
| ③ | **경쟁 서비스** | 공식 문서 변경점 (computer use · Copilot Actions) | 수동 |
| ④ | **강의 개념 매핑** | 새 개념이 우리 어디에 붙나 · **왜 안 붙였나** | 수동 |
| ⑤ | **우리 지표 추이** | `logs/pluiz.log`의 `턴 완료` 줄 (소요 · LLM 횟수 · 토큰) | 로그 grep |

> **①의 «도구 호출 신뢰도»가 우리에게 가장 중요한 축이다.** BL-19가 정확히 그 문제였다 —
> 나쁜 구간의 모델이 도구를 안 부르고 *"지켜볼게요"* 라고만 말했다. 모델을 바꿀지 말지의
> 판단 근거가 여기 쌓인다.

## 기록 규율 — ADR과 같다

각 항목을 **세 줄로** 적는다. 세 번째 줄이 핵심이다.

```
무엇이 바뀌었나 :
영향이 있나     :
조치했나        :  (안 했으면 **왜 안 했는지**)
```

> **«안 했으면 왜»를 빼면 이 폴더는 링크 모음이 된다.**
> *"minor가 9개 벌어졌지만 올리지 않았다 — 시연 3주 전이고 lock의 존재 이유가 재현성이라서"*
> 이렇게 적혀 있어야 졸작 「SW 품질 · 유지보수성」과 「한계점」의 재료가 된다.
> 판단하지 않고 미룬 것과, 판단해서 안 한 것은 다르다.
