# 구글 계정 연결 — **일정 읽기 · 메일 읽기를 켜는 법** (사용자 몫 · 약 15분)

> 📍 [문서 허브](README.md) · 쓰는 곳: `tools/google_auth.py`(권한) · `tools/calendar.py` · `tools/gmail.py`
> 관련: [페르소나 §3-D·§3-E](planning/페르소나_직장인.md)

한 번만 하면 됩니다. **일정과 메일이 같은 설정을 씁니다** — 따로 두 번 하지 않습니다.

---

## 0. 🚨 먼저 — 무엇을 허락하는 것인지

이 설정은 **Pluiz 가 내 구글 계정의 일정과 메일을 읽을 수 있게** 합니다.
그래서 처음에 주는 권한을 **읽기까지만** 끊어 둡니다.

| 단계 | 권한 | 할 수 있는 것 | 할 수 **없는** 것 |
|---|---|---|---|
| **지금** | `calendar.events` | 일정 읽기 · 추가 | — |
| **지금** | `gmail.readonly` | 메일 목록·내용 읽기 | 🔒 **보내기 · 초안 쓰기 · 지우기** |
| 나중 | `gmail.compose` | 초안 쓰기 | — |

> ### 🚨 **«초안만 쓰고 발송은 못 하는» 권한은 구글에 없다**
>
> `gmail.compose` 는 이름과 달리 **발송 권한을 포함한다.** 그래서
> *"회신 초안 써줘"* 를 켜는 순간 **계정 수준에서는 발송도 가능해진다.**
>
> 🔑 **그 경계는 우리 코드가 지킨다** — `gmail_send` 라는 **도구를 아예 만들지 않으면**
> 모델이 부를 수단이 없다. `close_app`/`force_close_app` 을 이름이 다른 도구로 가른 것과
> 같은 규칙이다([승인의 경계 §4-2](design/G-05-19_승인의_경계.md)).
>
> ⏸️ **그래서 1단계는 `gmail.readonly` 뿐이다.** 초안이 실제로 필요해지면 그때
> **눈을 뜨고** 권한을 올린다. 지금 미리 올려 두지 않는다.

📌 **받은 자격증명 파일은 저장소에 안 올라갑니다** — `.gitignore` 에 걸려 있는지
아래 §4에서 확인합니다.

## 1. 구글 클라우드에서 프로젝트 만들기 (약 5분)

1. <https://console.cloud.google.com/> 접속 — 구글 계정으로 로그인
2. 화면 위쪽 **프로젝트 선택** → **새 프로젝트**
3. 이름은 아무거나 (예: `Pluiz`) → **만들기**
4. 만들어지면 그 프로젝트가 선택돼 있는지 확인 (위쪽에 이름이 보입니다)

---

## 2. 쓸 기능 켜기 (약 3분)

왼쪽 메뉴 **API 및 서비스 → 라이브러리** 에서 둘을 찾아 **사용 설정**을 누릅니다.

| 찾을 것 | 왜 |
|---|---|
| **Google Calendar API** | *"오늘 일정 뭐야"* |
| **Gmail API** | *"밤새 온 메일 있어?"* |

⚠️ **둘 다 켜 두세요.** 나중에 하나 더 켜려면 이 과정을 다시 와야 합니다.

---

## 3. 동의 화면과 자격증명 (약 5분)

### 3-1. OAuth 동의 화면

왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**

| 칸 | 넣을 것 |
|---|---|
| User Type | **외부**(External) |
| 앱 이름 | `Pluiz` |
| 사용자 지원 이메일 | 본인 이메일 |
| 개발자 연락처 | 본인 이메일 |

**범위(Scopes)** 단계에서 아래 둘을 추가합니다.

    .../auth/calendar.events
    .../auth/gmail.readonly

🚨 **`gmail.compose` 나 `gmail.send` 는 지금 넣지 않습니다** (§0 참조).

**테스트 사용자** 단계에서 **본인 구글 계정을 추가**합니다.
⚠️ 이걸 빼면 나중에 로그인할 때 *"확인되지 않은 앱"* 에서 막힙니다.

### 3-2. 자격증명 받기

왼쪽 메뉴 **API 및 서비스 → 사용자 인증 정보**

1. **사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
2. 애플리케이션 유형: **데스크톱 앱**
3. 이름은 아무거나 → **만들기**
4. **JSON 다운로드**

## 4. 파일 넣고 확인하기 (약 2분)

내려받은 JSON 을 **이름을 바꿔서** 프로젝트 맨 위 폴더에 둡니다.

    C:\pluiz_v2\calendar_credentials.json

> 🔑 **이름이 `calendar_credentials.json` 이어야 합니다.** 일정과 메일이 같은 파일을 씁니다
> (이름이 «calendar»인 것은 캘린더가 먼저 생겼기 때문이고, 바꾸면 기존 코드가 못 찾습니다).

### 🚨 저장소에 안 올라가는지 확인

터미널에서 한 줄이면 됩니다.

    git status --short

`calendar_credentials.json` 이 **목록에 안 보이면 정상**입니다.
보이면 **커밋하지 말고** 알려 주세요 — `.gitignore` 를 고쳐야 합니다.

## 5. 첫 연결 (약 1분) — **한 번만**

서버를 띄운 뒤 Pluiz 에게 말합니다.

    "오늘 일정 뭐야"     또는     "밤새 온 메일 있어?"

🔑 **둘 중 아무거나 해도 됩니다.** 일정과 메일이 **같은 인증 한 번**을 씁니다
(`tools/google_auth.py` 가 두 권한을 한꺼번에 요청합니다).

그러면 **브라우저가 저절로 열리고** 구글 로그인 화면이 뜹니다.

| 나오는 것 | 할 것 |
|---|---|
| 계정 선택 | 본인 계정 |
| *"Google에서 확인하지 않은 앱입니다"* | **고급 → Pluiz(안전하지 않음)으로 이동** |
| 권한 동의 | **허용** |

✅ 끝나면 `calendar_token.json` 이 생기고, **다음부터는 안 묻습니다.**

> ⚠️ *"확인되지 않은 앱"* 경고는 정상입니다 — 구글 심사를 받지 않은 개인 앱이라
> 그렇습니다. §3-1 에서 **테스트 사용자에 본인을 넣어 뒀기 때문에** 통과됩니다.

## 6. 안 되면

| 증상 | 원인 | 할 것 |
|---|---|---|
| *"캘린더를 읽으려면 구글 계정 연결이 한 번 필요해요"* | 파일이 없거나 이름이 다르다 | §4 의 경로·이름 확인 |
| 브라우저에서 **403 access_denied** | 테스트 사용자에 본인이 없다 | §3-1 마지막 단계 |
| *"캘린더를 읽지 못했어요 (HttpError)"* | API 를 안 켰다 | §2 |
| 한참 뒤 **토큰 만료** | 테스트 모드는 토큰이 7일마다 끊긴다 | 다시 물으면 브라우저가 또 열립니다. 정상입니다 |

📌 **마지막 줄이 중요합니다** — 구글 OAuth 동의 화면을 «테스트» 상태로 두면
**리프레시 토큰이 7일**입니다. 전시회(11/24) 직전에 한 번 다시 연결해야 할 수 있습니다.
⚠️ **부스 당일 아침 점검 목록에 넣어 두세요.**

## 7. 연결하면 무엇이 되나

| 말 | 무엇이 되나 |
|---|---|
| *"오늘 일정 뭐야"* · *"내일 회의 있어?"* | 일정 읽기 |
| *"내일 3시 회의 잡아줘"* | 일정 추가 (원래 되던 것 — 이제 브라우저 없이 바로 등록됩니다) |
| *"밤새 온 메일 있어?"* | 최근 메일 목록 (보낸이·제목·시각) |
| *"김 팀장한테 온 메일 있어?"* | 보낸 사람으로 찾기 |
| *"안 읽은 메일 뭐 있어?"* | 안 읽은 것만 |
| *"그 메일 뭐라고 왔어?"* · *"요약해줘"* | 메일 하나를 골라 본문 읽기 |

## 8. 🔒 이 문서가 약속하지 않는 것

- 🔒 **메일 발송은 지금 구조로 불가능합니다.** 권한(`gmail.readonly`)에도 없고,
  `gmail_send` 라는 **도구 자체를 안 만들었습니다.** 둘 중 하나만으로는 부족해서
  둘 다 막아 뒀습니다 — 권한만 조이면 나중에 범위를 넓히는 순간 도구가 생기고,
  도구만 없애면 권한이 남습니다.
- 🔒 **초안 쓰기도 안 됩니다.** §0 에 적었듯 구글에 «초안만»인 권한이 없어서,
  그걸 켜면 발송도 같이 열립니다. 필요해지면 그때 따로 정합니다.
- 🚨 **메일 내용은 요약을 만들기 위해 AI 모델로 올라갑니다.** 이건 «읽어 줘»라는
  기능의 성질상 피할 수 없습니다. 대신 셋을 지킵니다 — 주민번호·카드번호·API 키는
  **올라가기 전에 가리고**, 목록은 제목까지·본문은 앞 1,500자까지만 보고,
  **내용은 로그에 안 남깁니다**(몇 통인지·몇 자인지까지만).
- ⚠️ **메일 내용은 소리로도 읽힙니다.** 사무실에서는 이어폰을 쓰시거나
  *"소리 꺼 줘"* 를 먼저 하세요.
