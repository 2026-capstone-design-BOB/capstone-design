직접 구현의 증거 — "라이브러리로 안 됐던 것들"

"API 붙인 것 아니냐"는 질문에 대한 구체적 답변입니다. 라이브러리가 해결 못해 직접 짜야 했던 케이스들.

① 창 포커스 권한
문제: 다른 앱이 포그라운드일 때 SetForegroundWindow() 호출해도 창이 안 올라옴
왜 라이브러리로 안 되나: Windows 보안 정책. pyautogui·psutil 모두 이 문제를 해결하지 않음
우리 해결: 현재 포그라운드 스레드에 AttachThreadInput으로 임시 attach → 권한 획득 후 창 전환 → detach. ctypes user32 직접 호출.
② 한국어 키보드 입력
문제: pyautogui.typewrite()는 ASCII만 지원. 한국어 직접 입력 시 글자 깨짐
왜 라이브러리로 안 되나: pyautogui 공식 문서에 한국어 미지원 명시. 대안 라이브러리 없음
우리 해결: 한국어 텍스트를 클립보드에 복사(pyperclip) → Ctrl+V로 붙여넣기 → 원래 클립보드 내용 복원. 사용자에게 투명하게 동작.
③ LangGraph thread 오염 자동 복구
문제: 예외 발생 시 불완전 체크포인트 저장 → 이후 요청부터 에이전트 무한루프
왜 라이브러리로 안 되나: LangGraph 문서에 없는 케이스. MemorySaver 내부 저장소를 직접 접근해야만 해결 가능
우리 해결: 오염 패턴 자동 감지 → MemorySaver storage 키 직접 삭제(_clear_thread) → 새 thread_id로 재시도. 사용자 개입 없이 자가 복구.
④ STT 자동 전환 (하이브리드)
문제: Google STT는 오프라인에서 죽음. faster-whisper만 쓰면 온라인보다 느리고 정확도 낮음
왜 라이브러리로 안 되나: 두 라이브러리 모두 "자동 전환" 기능 없음. 네트워크 상태 감지 + 전환 로직 자체 설계 필요
우리 해결: 네트워크 체크(10초 TTL 캐싱) → 온라인이면 Google STT, 오프라인이면 Whisper. 서버 시작 시 Whisper 백그라운드 프리로드.

개발 과정 문제 ① — exec() vs 도구 방식

개발 과정 문제 ② — 그 외 기술 도전과 해결

구조 재설계 이후에도 라이브러리로 해결 안 되는 문제들이 남아있었습니다.

① Electron file:// → 서버 사이드 STT 전환
문제: Web Speech API는 HTTPS 보안 컨텍스트 필요. file:// 프로토콜에서 마이크 접근 불가.
해결: STT를 서버로 이전. MediaRecorder webm blob → POST /voice → Whisper 처리.
의미: 단순 버그픽스가 아닌 아키텍처 결정. Electron 한계를 서버 사이드로 우회.
② Windows SetForegroundWindow 권한 제한
문제: 다른 앱이 포그라운드일 때 창 활성화 불가. Windows 보안 정책.
해결: AttachThreadInput 트릭 — 포그라운드 스레드에 임시 attach → 권한 획득 → detach.
의미: Windows 저레벨 API 직접 제어. 어떤 라이브러리도 이 문제를 해결하지 않음.
③ LangGraph thread 오염 → 자동 복구
문제: 예외 발생 시 불완전 체크포인트 저장 → 이후 요청부터 무한루프.
해결: 오염 패턴 자동 감지 → MemorySaver storage 직접 삭제 → 새 thread_id로 재시도.
의미: LangGraph 문서에 없는 케이스. 자가 복구 → 사용자 개입 불필요.
