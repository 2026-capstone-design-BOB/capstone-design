## 1. 무엇을 푸는가

페르소나 표에서 **⛔ 셋이 같은 것 하나를 기다리고 있었다.**

| 어디 | 발화 | 막혀 있던 이유 |
|---|---|---|
| §3-E | *"30분 뒤에 알려줘"* | 턴이 끝난 뒤에 도는 것이 없다 |
| §3-F | *"끝나면 알려줘"* | 오래 걸리는 일을 맡길 데가 없다 |
| §3-J | *"메일 오면 알려줘"* | `watch_screen` 은 **화면에 보이는 것**만 본다 |

셋 다 「턴이 끝난 뒤에 무슨 일이 일어나고, 그때 우리가 먼저 말을 건다」는 한 가지
구조를 기다리고 있었다. 그래서 하나로 만들었다.

## 2. 🚨 그래프 «밖» — 절대규칙 1과 정면으로 부딪히는 자리

[피벗 제안](../planning/피벗_제안_2026-09-21.md)은 *"`ToolNode` 를
`asyncio.create_task` 로 바꾸라"* 고 했다. 그것이 **정확히 노드를 async 로 만드는
일**이고, LangGraph `interrupt`(사람 승인)는 sync 경로에서만 안정 동작한다
([절대규칙 1](../../CLAUDE.md)).

| | 제안한 대로 | 실제로 한 것 |
|---|---|---|
| 어디서 도나 | `ToolNode` 안에서 async | **그래프 밖 스레드** (`core/worker.py`) |
| 그래프는 | 기다린다 → async 여야 한다 | 약속을 **얹고 sync 인 채로 즉시 끝난다** |
| 승인 노드 | 🚨 깨진다 | ✅ **한 줄도 안 건드렸다** |
| 사용자 경험 | «백그라운드에서 할게요» | 똑같다 |

`tests/test_worker.py` [24]가 이것을 지킨다 — `graph.py` 에 `async def` 가 없고,
워커 도구 셋이 전부 sync 다.

## 3. 🔑 알림 표면은 **이미 있었다**

페르소나 §3-E 가 *"알림 표면 자체가 없다"* 라고 적어 두고 있었는데,
**절반은 이미 있었다.** 화면 감시가 `{"type": "notify"}` 로 UI 에 말을 걸고
있었고, `main.py` 가 그 길에 세 가지를 이미 걸어 뒀다.

1. **마스킹** — 알림 문장은 에이전트를 안 거치고 나가므로 여기서 한 번 더 가린다
2. **TTS** — 사용자가 화면을 안 볼 때 쓰는 기능이라 소리까지 있어야 전달된다
3. **UI 가 없으면 보관** — 연결이 없으면 버리지 않고 다음 연결 때 전한다

**그래서 두 번째 채널을 안 만들었다.** 만들었다면 저 셋을 다시 구현하게 되고,
언젠가 한쪽만 고쳐진다([BL-64](../BACKLOG.md)가 정확히 그 모양이었다).

⚠️ 대신 UI 에서 한 가지가 어긋났다 — 알림 처리기가 «감시 배지 끄기»를 같이 하고
있어서, **워커 알림이 돌고 있는 화면 감시를 꺼진 것처럼 보이게** 했다. 알림에
`source: "worker"` 를 실어 가르고, 약속 개수는 `worker_state` 라는 별도 배지로 뺐다.

## 4. 구조 — 약속 하나가 곧 «깨어날 시각 + 할 일»

```
도구(sync)  ──add()──▶  BackgroundWorker  ──때가 되면──▶  spawn(스레드)
   │                        │                                  │
   └─ 즉시 리턴              └─ 1초마다 tick                     └─ run()
                                                                  │
                            notify(text, reason, what) ◀──────────┘
                                   │
                            {"type":"notify"} → main.py → 마스킹 · TTS · /ws
```

종류는 둘뿐이다.

| | `KIND_ONCE` | `KIND_POLL` |
|---|---|---|
| 언제 | 한 번 깨어나 실행하고 끝 | 주기적으로 확인하다 **찾으면** 끝 |
| 쓰는 곳 | 알림 · 백그라운드 작업 | 메일 기다리기 |
| `run()` 이 `done: False` 를 주면 | **그래도 끝난다**(아래 §6-①) | 간격 뒤 다시 부른다 |

작업 하나가 **자기 스레드**에서 돈다. 스케줄러 스레드에서 직접 부르면 오래 걸리는
작업 하나가 **다른 모든 약속을 멈춰 세운다** — 30분 알림이 리서치 뒤로 밀린다.

## 5. 정직성 — 감시(screen_monitor)에서 배운 것을 그대로 가져왔다

이 기능은 **사용자가 보고 있지 않을 때** 돈다. 사용자는 «기다리는 줄 알고 아무것도
안 하고 있다». 그래서 이 저장소가 반복해서 데인 결함(확인 안 하고 됐다고 말하기 —
BL-12 · BL-15)이 여기서 가장 위험하다.

| 규칙 | 어떻게 |
|---|---|
| **조용히 안 끝난다** | 완료·실패·상한 — 어떤 이유로 끝나든 알린다 |
| **취소는 안 알린다** | 본인이 시킨 일이다. 알리면 그게 소음이다 |
| **약속할 때 상한을 같이 말한다** | *"몇 분마다 확인하고 언제 스스로 멈추는지"* |
| 🚨 **«닫으면 사라져요»를 미리 말한다** | 디스크에 저장하지 않는다. **저장하는 척이 더 나쁘다** |
| **못 봤다고 «없다»고 하지 않는다** | 상한에 닿으면 *"N번 확인했는데 아직 소식이 없어서"* |
| **못 받으면 못 받았다고 한다** | 자리가 차면 남의 약속을 **밀어내지 않고** 거절하고 목록을 보여 준다 |
| **못 지킬 약속은 안 받는다** | 12시간 너머는 잘라서 받지 않고 거절한다 — 서버가 그렇게 오래 안 산다 |

## 6. 결정 셋 — 왜 이렇게 했나

### ① 한 번짜리는 «아직»을 인정하지 않는다

`run()` 이 `{"done": False}` 를 줘도 `KIND_ONCE` 는 끝낸다. 인정하면 **한 번 하기로
한 일이 무한히 되풀이될 수 있다.** 되풀이는 `KIND_POLL` 의 일이고, 그쪽에는 시간·
횟수 상한이 걸려 있다.

### ② 되풀이 간격에는 **바닥**이 있다 (60초)

모델이 *"5초마다 확인해"* 라고 부르면 바닥까지만 내려간다. 간격이 곧 API 호출량이라
여기가 없으면 **할당량이 조용히 탄다.** 상한을 «모델이 안 그럴 것»에 맡기지 않는다.

### ③ **돌고 있는 중이어도 시간 상한을 건다**

처음에는 «도는 중인 작업은 건드리지 않는다»였는데, 그러면 안 끝나는 작업 하나가
*«아직 하고 있겠지»* 인 채로 **영원히 남는다.** 사용자는 기다리는데 아무도 말을 안
건다 — 이 기능이 고치려던 바로 그 상태다. 그래서 상한에서 버리고 **버렸다고 알린다.**
버린 뒤 늦게 끝나면 결과를 조용히 접는다(두 번 말하지 않는다).

## 7. 🔒 백그라운드 작업 — 가른 기준은 «위험한가»가 아니다

`do_in_background` 는 **제한된 도구만 가진 별도 에이전트**에게 일을 시킨다
(`core/tool_registry.py` 의 `get_background_tools()`).

### 7-1. 승인 대상은 **여기 있을 수가 없다**

뒤에서 도는 턴이 `interrupt` 를 걸면 물어볼 사람이 그 자리에 없다 —
**영영 안 끝난다.** 도구를 안 주는 것이 «안 부르기로 약속»보다 강하다
(`gmail_send` 를 아예 안 만든 것과 같은 규칙).

### 7-2. 🚨 그런데 진짜 기준은 **«사용자의 손과 눈을 뺏는가»** 였다

맡긴 일이 도는 동안 사용자는 **다른 창에서 자기 일을 하고 있다.** 그런데

- `type_text` 는 **지금 포커스된 창**에 글자를 넣고
- `open_app`·`switch_window` 는 창을 앞으로 꺼내고
- `set_volume` 은 듣고 있던 소리를 바꾸고
- `describe_screen` 은 **남의 일 화면**을 외부 LLM 으로 보낸다

하나도 «위험 도구»가 아닌데 **전부 사용자가 하던 일을 망친다.** 그래서 목록을
«되돌릴 수 있나»가 아니라 **«내 손이 지금 거기 있나»** 로 갈랐다.

남은 것은 **찾고 · 읽고 · 파일로 남기는** 15개다.

### 7-3. 허용목록이다 — 새 도구는 기본으로 «안 준다»

금지목록이면 다음에 누가 도구를 더할 때 **가만히 있어도 백그라운드에 들어간다.**
빠뜨리는 쪽이 안전한 방향이라 허용목록으로 뒀고, `tests/test_worker.py` [20]이
«적어 둔 이름이 전부 실재하는가»를 따로 지킨다(오타 하나가 조용히 도구를 뺀다).

### 7-4. 앞단 설정에서 셋만 덮는다

| | 왜 |
|---|---|
| `agent_timeout` 45초 → 10분 | 뒤에서 도는 일은 45초로 안 끝난다. 상한은 워커가 따로 건다 |
| `vision_verify_enabled` → off | 백그라운드는 화면을 안 본다(§7-2) |
| 캐시 → off | ① 뒤에서 돈 턴을 학습하면 앞단이 «뒤에서 할게요»를 즉답으로 내놓는다 ② 반대로 캐시가 먼저 채 가면 맡긴 일이 **안 돌고** 옛 답만 온다 |

세션 기록(`memory/session.py`)에도 안 남긴다 — 사용자가 **하지 않은 말**이
대화 기록에 생긴다. 결과는 알림으로 화면에 그대로 나오므로 잃는 것이 없다.

📌 **앞단의 관문은 그대로 산다.** 같은 그래프를 쓰기 때문이다. 이 시험을 처음 쓸 때
가짜 LLM 이 도구를 안 부르고 *"✓ …"* 로 답했더니 **BL-61(지어냄 방어)이 막았다** —
백그라운드가 무르게 도는 별도 경로가 아니라는 증거다.

## 8. 📬 메일 기다리기 — «오면»은 미래를 가리키는 말이다

첫 확인은 **기준을 잡는 것**이고 알리지 않는다. 쌓여 있던 메일을 «새 메일»이라고
하면 그게 거짓말이다. 그리고 셋을 더 지킨다.

- **본문을 안 싣는다.** 알림은 «왔다»까지다 — 이 문장은 **소리로도 읽힌다.**
- **연결이 안 된 것은 되풀이하지 않는다.** 재시도해도 안 풀린다. 바로 접고 이유를 말한다.
- **연속 3번 실패하면 포기하고 알린다.** 계속 실패하면서 도는 것이
  «기다리는 줄 알았는데 안 보고 있었다»가 된다.

## 9. 남은 것

- **알림이 Windows 토스트가 아니다.** 우리 창을 앞으로 꺼내 말한다(화면 감시와 같은
  방식). 토스트는 전시회 전에 볼 값어치가 있는지부터 따진다 — 창을 꺼내는 쪽이
  TTS·마스킹을 이미 타고 있다.
- **약속이 서버 수명을 못 넘는다.** 디스크 저장은 안 했다. 지금은 그 사실을 말하는
  것으로 막고 있다.
- **되살리기(재시도)가 없다.** 실패하면 실패했다고만 한다. 자동 재시도는 «두 번
  했는지 몰랐다»를 낳아서, 먼저 실기에서 어떤 실패가 나는지 보고 정한다.
- **평가 문장이 없다.** 새 도구 다섯이 실제로 «제대로 불리는지»는 아직 안 쟀다
  (9/24 에 15개를 늘리며 남긴 것과 같은 빚이다).
