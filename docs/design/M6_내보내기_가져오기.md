## 1. 배경 — 클라우드를 «안 하기로» 한 것의 대안

2026-09-08에 제품 방향 3건을 확정하며 **클라우드 동기화를 «안 함»으로 정했다.**
미룬 게 아니라 버린 것이고, *"3주 안에 포인팅을 제대로 만들려고 이 셋을 버렸다"* 가
그대로 한계점 분석이 된다.

다만 «안 한다»로 끝나면 심사에서 *"그럼 PC를 바꾸면 학습한 게 다 날아가나요?"* 라는
질문에 답할 수 없다. **파일 하나로 옮길 수 있으면 답이 된다** —
*"설계상 로컬 우선이고, 이동은 파일로 합니다."*

## 2. 무엇이 사용자의 «것»인가 — 실측

| 파일 | 무엇 | 옮기나 |
|---|---|---|
| `cache/command_cache.json` | 학습된 명령 캐시 | ✅ **핵심** |
| `cache/favorites.json` | 즐겨찾기 | ✅ |
| `memory/session.db` | 대화 히스토리(SQLite) | ⚠️ **옵트인** |
| `.env` | **API 키** | 🚫 **절대** |
| `logs/pluiz.log` | 로그 | 🚫 마스킹을 안 거친다 |
| `services/wakeword_model.npz` | 웨이크워드 모델 | 🚫 코드가 제공한다 |

### 2-1. 대화 히스토리를 기본에서 뺀 이유

캐시는 *"이 말은 이 도구"* 라는 **규칙**이고, 히스토리는 **사용자가 실제로 한 말**이다.
성격이 다르다. 이동의 목적(다른 PC에서 학습을 이어 쓰기)은 캐시·즐겨찾기로 달성되고,
히스토리는 **없어도 목적을 해치지 않는다.** 그래서 기본에서 빼고 **명시적으로 켤 때만**
담는다. 파일을 남에게 보내거나 클라우드에 올릴 수 있다는 걸 감안하면 이쪽이 맞다.

### 2-2. `.env`를 «빼는» 게 아니라 «넣을 수 없게» 한다

블록리스트로 `.env`를 거르면, **다음에 민감한 파일이 생겼을 때 조용히 새어 나간다.**
그래서 **allowlist**로 간다 — 목록에 적힌 것만 담기고, 새 파일은 **적어야 담긴다.**

> 규율은 확률을 올릴 뿐이고 보장하는 건 구조다 — [BL-29](BL-29_도구_결과_계약.md)와 같은 모양.

## 3. 🚨 핵심 통찰 — **가져오기는 학습의 다른 입구다**

2026-09-10 아침에 [BL-27](../BACKLOG.md)을 고쳤다. 승인 응답 `'그래'`가 `close_app`으로
학습돼 있었고, `is_learnable_utterance()`(L1·L2·L3)와 `has_contrast_marker()`로 막았다.

**그 필터는 `learn()` 경로에만 있다.**

가져오기가 캐시 파일을 그대로 받아들이면, **다른 PC에서 오염된 엔트리가 필터를 우회해
들어온다.** 그 PC가 BL-27 이전 버전이었다면 `'그래' → close_app`이 그대로 온다.
그러면 오늘 고친 것이 **파일 하나로 되돌려진다.**

> **결정: 가져오는 모든 엔트리는 `learn()`과 똑같은 게이트를 통과해야 한다.**
> 통과 못 한 건 조용히 버리지 않고 **몇 개를 왜 버렸는지 보고한다.**

이게 이 ADR에서 제일 중요한 줄이다. 나머지는 지퍼 파일 다루기다.

## 4. 대안 비교 — 충돌을 어떻게 다루나

| | 안 | 평가 |
|---|---|---|
| **A** | **통째로 덮어쓴다** | ✗ 되돌릴 수 없다. 받는 쪽에서 쌓은 학습이 사라진다 |
| **B** | **병합 — 기존 우선** | ✅ **채택.** 안전이 기본이다. 같은 패턴이 양쪽에 있으면 **원래 것을 지킨다** |
| **C** | 병합 — 들어온 것 우선 | ✗ 조용한 덮어쓰기다. 원할 때만 명시적으로(§5-3) |

### 시드는 옮기지 않는다

시드(`is_seed=True`) 37개는 **코드가 제공한다.** 내보낸 시드를 다른 PC에 넣으면
그 PC의 시드 버전과 충돌하고, 시드가 바뀌었을 때 **낡은 시드가 새 시드를 덮는다.**
→ **동적 학습분(`source == "dynamic"`)만 옮긴다.** 이게 실제로 사용자의 «것»이다.

## 5. 결정

### 5-1. 형식

```
pluiz-export-20260910-1432.zip
├── manifest.json      ← 버전 · 만든 날짜 · 담긴 항목 · 개수
├── command_cache.json ← 동적 학습분만
├── favorites.json
└── session.db         ← 히스토리를 켰을 때만
```

`manifest.json`이 **없으면 가져오기를 거절한다.** 아무 zip이나 받으면
사용자가 엉뚱한 파일을 넣었을 때 조용히 이상해진다.

### 5-2. 가져오기 절차

1. `manifest.json` 확인 — 없거나 버전이 안 맞으면 **아무것도 안 하고** 거절
2. **현재 상태를 먼저 백업**한다 (`cache/command_cache.backup-<날짜>.json`)
   — 되돌릴 수 없는 변경 앞에서는 되돌릴 길을 만들어 둔다
3. 엔트리마다 **§3의 게이트**를 통과시킨다
4. 병합(기존 우선) → **무엇을 몇 개 했는지 보고한다**

### 5-3. 안 하기로 한 것

- **도구로 만들지 않는다.** 음성으로 *"내보내줘"* 를 부를 수 있게 하면 도구가 41개가
  되는데, [도구 사용 실측](../research/2026-09_도구사용_실측.md)에서 **등록 40개 중
  13개만 실사용**이라는 걸 확인하고 *"도구를 더 만들지 않는다"* 고 정했다.
  ⚠️ 게다가 **가져오기는 되돌릴 수 없는 상태 변경**이다. LLM이 부를 수 있게 만들면
  HITL 승인이 필요해지고, 그건 이 기능이 감당할 복잡도가 아니다.
  → **UI 버튼 + API만.** 사람이 파일을 고르는 흐름이 맞다.
- **자동 동기화·클라우드 업로드는 하지 않는다** (그게 «안 함»으로 정한 그것이다).
- **덮어쓰기 모드를 기본으로 두지 않는다.** `mode=replace`로 명시할 때만.

## 7. 남는 한계

- **세션 히스토리는 SQLite라 병합하지 않는다.** 켰을 때 **파일을 통째로 바꾼다.**
  대화 두 벌을 시간순으로 섞는 건 이 기능이 감당할 일이 아니다 — 그렇게 적어 둔다.
- **버전이 올라가면 옛 zip을 못 읽을 수 있다.** `manifest`에 버전을 넣는 이유이고,
  못 읽으면 **거절하되 왜인지 말한다.** 조용히 반쯤 가져오는 것보다 낫다.
- **다른 PC의 `hit_count`를 그대로 받는다.** 통계가 섞이지만, 0으로 리셋하면
  «자주 쓰는 명령» 순서가 무너진다. 어느 쪽도 완전하지 않아 **덜 놀라운 쪽**을 골랐다.
