# BL-20 — 위험 도구를 거부해도 **안전한 호출은 살린다**

> 📍 [문서 허브](../README.md) · 결함: [BACKLOG BL-20](../BACKLOG.md) ·
> 관련 설계: [M1 아키텍처](M1_아키텍처_설계.md) · [M3 계획수립](M3_계획수립노드.md) ·
> [M3-1 단계완료판정](M3-1_단계완료판정.md) · 기록: [DEVLOG](../DEVLOG.md)
>
> **상태: 설계 확정 · 구현 전.** HITL을 건드리므로
> [WORKFLOW § 설계 결정](../WORKFLOW.md) 규칙대로 코드보다 이 문서가 먼저다.
>
> **한 줄**: 거부당한 호출만 마감하고, 안전한 호출은 **새 id로 재발행해** 다시 내보낸다.
> 「살려서 그대로 보낸다」는 안 된다 — 그러면 방금 거부한 삭제까지 같이 실행된다(§2).

## 1. 무슨 일인가

LLM이 한 `AIMessage`에 `[open_app, delete_file]`을 담으면, 사용자가 삭제를
거부했을 때 **메모장도 열리지 않는다.** 그런데 응답은 이것뿐이다:

> *"네, 삭제를 취소했어요."*

**앱이 안 열렸다는 사실은 아무도 말하지 않는다.** 사용자는 승인 흐름이 도는 걸
봤으니 *거부한 것만* 안 됐다고 믿는다.

두 줄이 맞물려 있다.

| 자리 | 코드 | 하는 일 |
|---|---|---|
| `route_after_agent` (`core/graph.py:1256`) | `any(c.get("name") in dangerous ...)` | **하나라도** 위험하면 배치 **전체**를 `hitl`로 보낸다 |
| `hitl._close_calls` (`core/graph.py:1180`) | `for c in calls` | 매달린 tool_calls를 **전부** 같은 사유로 마감한다 |

앞줄은 옳다 — 위험한 게 섞였으면 배치는 멈춰야 한다. **틀린 것은 뒷줄이다:
멈추는 것과 취소하는 것을 구분하지 않는다.**

### 1-1. 이건 이 프로젝트가 반복해서 데인 것의 뒤집힌 판본이다

지금까지 고쳐 온 사고는 **안 한 걸 했다고 말하는 것**이었다(BL-12 거짓 성공,
BL-19 감시 거짓말, BL-21 건너뛴 단계를 완료로 기록). BL-20은 그 거울상이다 —
**안 된 걸 말하지 않는 것.** 판정은 정직한데 **보고 범위가 좁다.**

### 1-2. 실기에서 관측된 적은 없다 — 그런데 지금 고친다

오늘은 LLM이 위험 도구와 안전 도구를 한 배치에 담는 일이 드물다.
그래서 2026-09-05에 발견하고도 기록만 남겼다. 상황이 바뀌었다:

- **계획 수립 노드가 기본 켜짐이 됐다**(2026-09-07). 복합 명령을 단계로 쪼개
  실행하므로 *"메모장 열고 test.txt 지워줘"* 류가 **정상 경로**가 된다.
- 로드맵의 **병렬 실행**은 이걸 **상시 경로**로 만든다.
  → [M3 ADR §5-2](M3_계획수립노드.md)가 *"병렬보다 BL-20이 먼저다"* 로 정한 이유다.

**관측되기를 기다리면, 관측되는 자리는 사용자의 실제 파일 앞이다.**

## 2. 왜 백로그의 「해결 후보」를 그대로 쓰면 안 되나

BACKLOG BL-20에 이렇게 적혀 있었다:

> `hitl`에서 안전한 호출은 마감하지 말고 **살려서 `tools`로 보낸다.**

**이대로 하면 고치려던 것보다 나쁜 사고가 난다.** 설치본
(`langgraph==1.2.4` / `langgraph-prebuilt==1.1.0`)의 `ToolNode._parse_input`:

```python
# site-packages/langgraph/prebuilt/tool_node.py:1257
latest_ai_message = next(
    m for m in reversed(messages) if isinstance(m, AIMessage)
)
```

**뒤에서부터 마지막 `AIMessage`를 찾아 그 `tool_calls`를 전부 실행한다.**
어떤 호출이 이미 ToolMessage로 마감됐는지는 **보지 않는다.**

그래서 「안전한 것만 마감하지 않고 `tools`로 보낸다」를 하면:

```
AIMessage[open_app, delete_file]         ← 마지막 AIMessage. 그대로다
ToolMessage(delete_file, "취소했습니다")   ← 삭제만 마감
                                          → ToolNode는 여전히 둘 다 실행한다
```

**방금 거부당한 삭제가 실행된다.** 승인 절차 전체가 무의미해진다.

> ⚠️ 이 프로젝트에서 **가장 비싸게 얻은 자산이 HITL이다**(무한루프 사고 포함).
> 여기를 «그럴듯한 후보»로 건드리면 안 되는 이유가 이 한 줄에 있다.

## 3. 설계 — 마감은 전부, 실행은 **재발행**으로

### 3-1. 원본 호출은 **전부** 마감한다 (짝 불변식)

`AIMessage.tool_calls`의 모든 id는 대응하는 `ToolMessage`를 가져야 한다.
하나라도 매달리면 Gemini 400이고, 그게 [절대규칙 3](../../CLAUDE.md)의 배경이다.
**그래서 «살린다»를 «마감하지 않는다»로 구현하지 않는다.**

다만 **마감 사유는 갈라 쓴다** — 지금은 안전한 호출까지
*"사용자가 삭제를 취소했습니다"* 를 받는데, 그건 사실이 아니다.

| 호출 | 마감 사유 |
|---|---|
| 위험(거부됨) | `사용자가 삭제를 취소했습니다.` (그대로) |
| 안전(살릴 것) | `승인 절차로 보류됐습니다. 이 호출은 아래에서 다시 실행됩니다.` |

### 3-2. 안전한 호출은 **새 id로 재발행한 `AIMessage`** 로 다시 내보낸다

```
AIMessage[open_app#c1, delete_file#c2]        ← 원본. 손대지 않는다
ToolMessage#c1 "보류됐습니다. 아래에서 다시 실행됩니다."
ToolMessage#c2 "사용자가 삭제를 취소했습니다."
AIMessage[open_app#c1-r]                      ← ★ 재발행. 이제 이게 마지막 AIMessage
```

`ToolNode`는 마지막 `AIMessage`만 본다(§2). 거기에 **안전한 호출만** 있으므로
`delete_file`은 실행될 수 없다 — 문구나 조건문이 아니라 **구조가** 막는다.

- 새 id는 원본 id + 접미(`f"{id}-r"`)로 만든다. 원본과 절대 겹치면 안 된다
  (겹치면 리듀서가 ToolMessage를 **교체**해 짝이 깨진다 — `visual_verify`가
  같은 성질을 반대 방향으로 이용한다).
- `content=""` · `tool_calls=[안전한 것들]`. 사람에게 보여줄 말은 여기 넣지 않는다.

### 3-3. 라우팅 — `hitl → tools`

`route_after_hitl`에 판정을 하나 더 둔다. **`approved`보다 뒤에** 본다.

```python
if d == "approved":          return "tools"
if d == "rejected_partial":  return "tools"   # ★ 재발행분 실행
if d in ("other_command", "not_found_partial", "not_found"):
    return "agent"
```

⚠️ **`decision` 값을 새로 만든다.** `rejected`를 재사용해 «재발행이 있으면 tools»로
분기하면 라우터가 messages를 뒤져 판단해야 한다. 상태에 적어 둔 값으로 갈리는 편이
싸고, 무엇보다 **테스트가 그 값을 직접 볼 수 있다.**

### 3-4. 거부 사실은 **문구가 아니라 플래그로** 전달한다

재발행 경로에서는 `hitl`이 *"네, 삭제를 취소했어요."* `AIMessage`를 **붙이지
않는다.** 뒤에 `tools → agent`가 이어져 agent가 최종 응답을 만들기 때문이다.
대신 `deletion_cancelled=True`를 켜서 `output_guard`가 접두를 붙이게 한다:

> **"삭제는 취소했어요. 메모장을 열었어요."**

이 배선은 이미 있다(`other_command` 분기가 같은 방식이다). 확인한 불변식:

- `output_guard`는 접두를 붙인 뒤 **반드시 `deletion_cancelled=False`로 되돌린다.**
- `input_guard`가 **매 턴 시작에** 다시 끈다.
  → 플래그가 턴을 넘어 새면 **실제로 삭제해 놓고 "취소했어요"라고 답한다.**
  그 사고는 이미 한 번 났고, 위 두 겹이 그때 생겼다.

## 4. 어디까지 살리나 — 분기별 결정

`hitl`이 끝나는 자리는 다섯이다. **둘만 재발행한다.**

| 판정 | 재발행 | 왜 |
|---|---|---|
| `approve` | — | 오늘도 배치 전체가 실행된다. **바뀌는 것 없음** |
| `reject` | ✅ | 사용자가 **거부한 것은 위험한 호출 하나**다. 나머지까지 취소해 달라고 한 적이 없다 |
| `not_found` | ✅ | **아무것도 거부되지 않았다.** 삭제 대상이 없었을 뿐인데 앱까지 안 열리는 건 근거가 없다 |
| `unclear` (재질문 소진) | ❌ | 답을 **한 글자도 못 읽었다.** 이 분기의 일은 *"다시 한 번 말씀해 주세요"* 이고, 되물으면서 동시에 도구를 실행하면 사용자가 무엇이 일어났는지 모른다. **안전 기본값을 유지한다** |
| `other_command` | ❌ | 사용자가 **다른 명령으로 갈아탔다.** 그 발화부터가 «이번 턴»이다([절대규칙 6](../../CLAUDE.md)). 지난 명령의 잔여 호출을 새 턴에 끼워 넣으면 `current_turn_messages()`가 오염된다 |

> 안전한 호출이 **하나도 없으면** 다섯 분기 전부 오늘과 **글자 그대로 같다.**
> 이게 이 설계의 안전장치다 — 새 경로는 «안전한 호출이 실제로 섞여 있을 때»만 열린다.

## 5. 부작용 하나 — M3-1의 계산이 부풀어 「못 했어요」가 사라진다

**이 절이 이 문서에서 가장 놓치기 쉬운 부분이다.**

[M3-1](M3-1_단계완료판정.md)은 진행도를 `min(커서, 이번 턴 도구 호출 수)`로 본다.
그 «호출 수»는 `turn_tool_call_count()` = 이번 턴 모든 `AIMessage`의
`tool_calls` 길이 합이다. 재발행하면 **안전한 호출이 두 번 세어진다.**

```
원본   AIMessage[open_app, delete_file]  → 2
재발행 AIMessage[open_app]               → 1
                                    합 3   ← 실제로 실행된 건 1개다
```

M3-1이 명시적으로 지키려던 **케이스 C(승인 거부)** 가 그대로 깨진다:

| | 커서 | 호출 수 | 판정 | 사용자가 듣는 말 |
|---|---|---|---|---|
| M3-1 설계(케이스 C) | 1 | 2 | 1 | *"다만 이건 못 했어요: 'test.txt 삭제'."* |
| **재발행을 그냥 넣으면** | 2 | 3 | 2 | **아무 말 없음** |

### 결정 — 재발행분은 **세지 않는다**

재발행 `AIMessage`에 표식을 달고 `turn_tool_call_count()`가 건너뛴다.

```python
AIMessage(content="", tool_calls=[...],
          response_metadata={"pluiz_reissued": True})
```

- `response_metadata`를 쓰는 이유: **provider로 올라가지 않는다.**
  `additional_kwargs`는 변환기가 요청에 실어 보낼 수 있어 피한다.
- 세는 규칙이 유지된다 — **호출 1개 = 진행 근거 1개.** 재발행은 새 진행이 아니라
  **같은 호출의 재시도**이므로 근거를 두 번 주면 안 된다.

> ⚠️ 이걸 «접두 문구(§3-4)가 어차피 말해 주니 괜찮다»로 넘기지 말 것.
> 접두는 **삭제**를 말하고, 접미는 **못 한 단계**를 말한다. 계획이 3단계인데
> 2단계에서 거부당하면 3단계는 아예 시도되지도 않았고, 그건 접두가 못 말한다.

## 6. 안 하기로 한 것

- **의존성 판정** — *"이 안전 호출이 거부된 삭제에 의존하나?"* 를 LLM이나 규칙으로
  가리지 않는다. 판정이 틀리면 사용자가 시킨 걸 조용히 안 하게 되고, 그게 바로
  지금 고치는 버그다. **의존하는 호출이 실패하면 도구가 정직하게 오류를 낸다** —
  그쪽이 조용한 취소보다 낫다. (대가: `[delete_file, list_directory]` 같은 배치에서
  목록이 삭제 전 상태로 나온다. 실행되지 않는 것보다 낫다고 본다)
- **사용자에게 되묻기** — *"삭제만 취소할까요, 전부 취소할까요?"* 는 승인 질문을
  두 겹으로 만든다. 음성 UI에서 승인은 이미 가장 비싼 상호작용이다.
- **`route_after_agent`에서 배치를 미리 쪼개기** — 안전한 것 먼저 실행하고 위험한
  것만 hitl로 보내는 방식. **거부했는데 앞의 것이 이미 실행돼 있는** 상태가 되고,
  이건 «되돌릴 수 없는 동작을 승인 전에 한다»라 방향이 반대다.
- **병렬 실행** — 제품 방향에서 «조건부 보류»였고 BL-20이 선행 조건이었다.
  이 문서가 그 조건을 푼다. 다만 여는 건 별건이다.

## 7. 이 설계를 쓰다가 발견한 것 — **BL-24 (신규)**

`hitl`은 위험 호출을 **하나만** 본다:

```python
dcall = next((c for c in calls if c.get("name") in dangerous), None)  # core/graph.py:1178
```

배치에 위험 호출이 **둘** 있으면(`[delete_file(a), delete_file(b)]`) **질문은 a에
대해서만** 나가고, 승인하면 `tools`가 **둘 다** 실행한다(§2의 그 성질 때문에).
**b는 사용자가 승인한 적이 없다.**

BL-20과 같은 계열이고 아직 관측된 적 없는 잠재 결함이라 **여기서 고치지 않고
[BACKLOG BL-24](../BACKLOG.md)로 분리한다.** 다만 §3-2의 재발행 기계가 그대로
답이 된다 — 승인된 호출만 재발행하면 나머지는 구조적으로 실행될 수 없다.

## 8. 구현 단계

각 단계가 끝날 때마다 mock 스위트가 통과해야 한다.

1. **순수 함수** (`core/graph.py`, 노드 밖) — 테스트가 그래프 없이 볼 수 있게.
   - `split_calls(calls, dangerous) -> (safe, risky)`
   - `reissue_message(safe_calls) -> AIMessage | None` (비었으면 `None`)
   - `turn_tool_call_count()`에 재발행 제외 규칙 추가 (§5)
2. **`hitl` 노드** — `_close_calls`를 사유 2종으로 가르고(§3-1),
   `reject`·`not_found`에서 재발행 + `decision`·`deletion_cancelled` 설정
3. **라우팅** — `route_after_hitl`에 `rejected_partial`·`not_found_partial` (§3-3)
4. **회귀 테스트** — `tests/test_hitl_graph.py`에 §4의 다섯 분기 + §5의 계산
5. **문서** — BACKLOG BL-20 해결 처리 · BL-24 신설 · README ADR 표 · DEVLOG

### 확인할 것

| | 무엇 | 왜 |
|---|---|---|
| ① | `[open_app, delete_file]` 거부 → **메모장이 열리고** `delete_file`은 실행 0회 | 이 문서의 존재 이유 |
| ② | 응답에 **"삭제는 취소했어요."** 접두가 붙는다 | 거부 사실이 사라지면 안 된다(§3-4) |
| ③ | 안전 호출이 **없는** 거부 → 오늘과 완전히 동일(`decision == "rejected"`) | 새 경로가 기존 경로를 침범하지 않는다(§4) |
| ④ | 승인(`approve`) 경로가 **한 글자도** 안 바뀐다 | HITL의 핵심 경로 |
| ⑤ | 계획 중간 단계 거부 → **접미 「못 했어요」가 그대로 나온다** | §5의 부작용이 실제로 막혔는지 |
| ⑥ | `other_command` → 재발행 **없음**, 계획도 지워진다 | §4 + [절대규칙 11](../../CLAUDE.md) |
| ⑦ | 모든 원본 `tool_call.id`에 `ToolMessage`가 하나씩 | 짝 불변식(§3-1). 깨지면 Gemini 400 |

### 예산 — `recursion_limit`은 안 올린다

거부 경로가 `hitl → output_guard`(2)에서 `hitl → tools → agent → output_guard`(4)로
**슈퍼스텝 2개** 길어진다. 계획이 켜져 있으면 상한이 24라 여유가 있고, 꺼져 있어도
`input_guard·fast_path·agent·hitl·tools·agent·output_guard = 7`로 10 안이다.
→ [M3 §1-1](M3_계획수립노드.md)이 이 계산을 처음 세운 자리다.

## 9. 되돌리기

`route_after_hitl`의 두 줄(`rejected_partial`·`not_found_partial`)을 지우면
재발행분이 실행되지 않고 오늘 동작으로 돌아간다. 재발행 `AIMessage`는 마지막에
남지만 아무도 읽지 않는다. **플래그로 끄는 스위치는 두지 않는다** — 켜고 끌
값어치가 있는 선택지가 아니라 **버그 수정**이다.
