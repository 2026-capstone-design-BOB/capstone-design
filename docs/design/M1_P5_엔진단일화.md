## 1. 배경

M1-P1.5에서 에이전트 코어를 다음과 같이 이관했다.

| | 구 엔진 | 신 엔진 |
|---|---|---|
| 파일 | `core/agent.py` (771줄) | `core/graph.py` + `core/graph_agent.py` |
| 클래스 | `PluizAgent` | `PluizGraphAgent` |
| 방식 | `create_react_agent` + 수동 `if/return` 전처리 | 명시적 `StateGraph` |
| 흐름 제어 | 함수 안에 분산 | 노드·엣지로 명시 |

이관 당시에는 **롤백 낙하산**으로 구 엔진을 남겨두고 `.env`의 `USE_GRAPH` 플래그로
전환할 수 있게 했다. [BACKLOG BL-05](../BACKLOG.md)에 "새 엔진 며칠 실사용 무결 확인 후 제거"로
기록돼 있었다.

## 2. 제거 결정의 근거

**신 엔진은 P2~P4를 거치며 충분히 검증됐다.**

| 단계 | 신 엔진 위에서 구현·검증된 것 |
|---|---|
| P2 | HITL 승인 (`interrupt`) — 구 엔진에는 아예 없는 기능 |
| P3 | OWASP 가드레일 4층 (인젝션·민감정보·출력검증·하이브리드 판정) |
| P4 | 캐시 동적 학습 + 관리 API |
| — | mock 스위트 158개 + CI 자동 실행 |

**남겨두는 비용이 이득을 넘어섰다.**

1. **신 엔진이 구 엔진에 의존하고 있었다.** `core/graph_agent.py`가 `_build_llm` 하나
   때문에 `from core.agent import _build_llm` 을 하고 있었다. 폴백이어야 할 모듈이
   주 경로의 의존 대상이 되어 있었던 것 — 롤백 낙하산으로서도 이미 깨진 상태였다.
2. **P2~P4 개선이 구 엔진에는 반영되지 않았다.** `USE_GRAPH=false`로 돌리면
   HITL도, 가드레일도, 캐시 학습도 없는 8월 이전 상태로 돌아간다.
   즉 실질적으로 **안전한 폴백이 아니었다.**
3. **삭제 도구 게이팅이 플래그에 묶여 있었다.** `tool_registry.py`가
   `use_graph`를 보고 `delete_file`/`delete_folder` 등록 여부를 정했다.
   엔진이 하나면 이 분기 자체가 불필요하다.
4. 설명 부담 — "엔진이 두 개이고 하나는 안 쓴다"를 매번 설명해야 했다.

## 3. 변경 내용

### 3-1. 새로 생긴 것
- **`core/llm.py`** — `build_llm()`. 구 엔진에 있던 `_build_llm`을 독립 모듈로 분리.
  provider별 패키지는 lazy import 하므로 mock 테스트가 LLM 패키지 없이 동작한다.

### 3-2. 사라진 것
| 대상 | 처리 |
|---|---|
| `core/agent.py` (771줄) | → **`archive/core_agent_v1.py`** 로 이동 (삭제 아님) |
| `core/factory.py` | 삭제 — 엔진이 하나면 선택할 게 없다 |
| `settings.use_graph` | 제거 |
| `.env`의 `USE_GRAPH` | 제거 (설정해도 무시됨) |

### 3-3. 수정된 것
| 파일 | 내용 |
|---|---|
| `core/graph_agent.py` | `core.agent` 의존 제거 → `core.llm.build_llm` 사용 |
| `main.py` | `get_active_agent()` → `get_graph_agent()` (3곳), `reset_active_agent()` → `reset_graph_agent()` |
| `core/tool_registry.py` | 삭제 도구를 플래그 없이 항상 등록. 안전장치는 `DANGEROUS_TOOLS` + `hitl` 노드가 담당 |
| `tests/test_sprint1_2.py` | 구 엔진 소스를 읽던 검증을 `core/graph.py` 기준으로 갱신 |

### 3-4. 안전장치는 어디로 갔나

이전에는 **"구 엔진에는 삭제 도구를 안 준다"** 가 안전장치의 일부였다.
이제 엔진이 하나이므로 안전장치는 전적으로 아래가 담당한다.

```
core/graph.py  DANGEROUS_TOOLS = {"delete_file", "delete_folder"}
                    ↓
              route_after_agent() 가 위험 도구 호출을 감지
                    ↓
              hitl 노드 → interrupt() → 사람 승인
                    ↓
              애매한 답변은 취소로 처리 (안전 기본값)
```

> ⚠️ **새 위험 도구를 추가할 땐 `DANGEROUS_TOOLS`에 반드시 추가할 것.**
> 여기 빠지면 승인 없이 실행된다. 예전에는 플래그가 이중 방어였지만 이제는 이 한 줄뿐이다.

## 4. 복원 · 참고 방법

**신 엔진에서 문제가 생겨 구 엔진 구현을 확인해야 할 때 여기를 보면 된다.**

### 4-1. 소스 위치 (가장 쉬움)

```
archive/core_agent_v1.py     ← 구 엔진 전체 771줄, 저장소에 그대로 있음
```

`import` 되지 않으므로 동작에 영향이 없고, 열어보기만 하면 된다.

### 4-2. git 이력에서 꺼내기

```bash
# 제거 직전(2026-09-01) 시점의 원본
git show 340b8a0:core/agent.py

# 마지막으로 실제 수정된 시점 (HITL 추가 직후)
git show 4a95e57:core/agent.py

# 특정 기능이 언제 들어왔는지
git log --follow --oneline -- core/agent.py
```

### 4-3. 구 엔진의 주요 구성 (뭘 찾아볼지)

| 위치 | 내용 | 신 엔진에서의 대응 |
|---|---|---|
| `_build_system_prompt()` | 시스템 프롬프트 | `graph.py: build_system_prompt()` |
| `_build_prompt_modifier()` | 히스토리 가공 | `graph.py: _prepare_messages()` |
| `_is_multi_app_command()` | 다중 앱 감지 | `fast_path.py: is_multi_app_command()` |
| `_route_deterministic()` | 정규식 라우터 | `router.py: route_deterministic()` |
| `_extract_tool_errors()` + `_patch_response_on_error()` | 도구 오류 보정 | `graph.py: verify_output()` **(둘이 하나로 통합됨)** |
| `_clear_thread()` | 히스토리 오염 복구 | `graph_agent.py: _clear_thread()` |
| `_record_fast_path()` | 캐시 결과를 기억에 기록 | **불필요** — 그래프에서는 `fast_path` 노드가 구조적으로 처리 |
| `_is_control_command()` + `_CONTROL_KEYWORDS` | 도구 미호출 시 재시도 | **미이관** — [BACKLOG BL-04](../BACKLOG.md) |
| `_build_llm()` | LLM 생성 | `core/llm.py: build_llm()` |

### 4-4. 진짜로 되돌려야 한다면

권장하지 않는다 — 구 엔진에는 HITL·가드레일·캐시 학습이 **전부 없다**(§2-2).
그럼에도 필요하다면:

```bash
git revert <이 작업의 커밋 해시>     # 되돌리기
# 또는 특정 시점으로
git checkout 340b8a0 -- core/agent.py core/factory.py
```
그 뒤 `main.py`의 import를 `core.factory`로 되돌리고 `settings.use_graph`를 복구해야 한다.

**대부분의 경우 "되돌리기"보다 "참고해서 신 엔진을 고치기"가 맞다.**
구 엔진에만 있던 동작을 되살리고 싶다면 해당 로직을 그래프 노드로 이관하는 편이 낫다.
