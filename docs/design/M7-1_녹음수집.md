## 1. ❓ 컴퓨터로만 해야 하나 — **아니다. 휴대폰도 똑같이 값지다**

**한때 내가 «실서비스가 노트북이니 수집도 노트북이어야 한다»는 식으로 말했는데 틀렸다.**
(2026-09-16, 사용자 반문: *"플루이즈라는 음성/발음만 학습하면 되는 거 아니야?"* — 맞는 말이다.)

### 진짜 지켜야 하는 불변식은 **하나**다

> **양성과 음성이 «같은 기기 · 같은 세션»에서 나와야 한다.**

2026-09-09에 실제 녹음을 **양성으로만** 넣고 학습했다가 «아무 말에나 깨어나는» 모델을 만들었다.
학습셋에서 진짜 마이크 오디오가 전부 양성이면, 모델은 단어를 배울 이유가 없다 —
**«합성음이냐 실제 마이크냐»만 구분해도 만점**이기 때문이다.

🔑 **녹음 페이지가 이걸 구조로 보장한다.** 한 사람이 한 자리에서
①「플루이즈」 ②비슷한 다른 말 ③잡담을 **같은 마이크로** 녹음한다.
그래서 **기기가 무엇이든 지름길이 생기지 않는다.**

### 기기를 기록하는 이유는 «게인»이 아니라 «평가»다

| | |
|---|---|
| **학습 데이터** | 기기가 **다양할수록 좋다.** 화자 다양성과 같은 이치다. 휴대폰·헤드셋·노트북 전부 환영 |
| **홀드아웃(평가)** | ⚠️ **여기만 실서비스와 같은 환경이 필요하다.** 전시·시연이 노트북 마이크로 도니, 홀드아웃에 노트북 녹음이 없으면 *"실제로 얼마나 되나"* 를 잴 수가 없다 → [M7 §5-2](M7_웨이크워드_재구축.md) |

- [ ] 📌 **노트북 녹음을 최소 3~5명 확보** — 학습용이 아니라 **홀드아웃용**이다

> 💡 **사람 수가 기기보다 훨씬 중요하다.** 폰으로 20명이 노트북으로 5명보다 낫다.
> 기기 균형은 홀드아웃을 고를 때 맞추면 된다.

## 2. ❓ 「소리가 작아요」가 떴는데 괜찮나 — **괜찮다. 임계가 틀렸었다**

2026-09-16, 사용자 보고: *"해 본 사람들 다들 입력 소리가 작다고 나온다고 한다."*
재 보니 **실제로 작은 사람은 아무도 없었다.**

### 숫자가 세 곳에서 서로 어긋나 있었다

| 어디 | 값 | 무엇 |
|---|---|---|
| **런타임** `services/wakeword.py` | **0.0015** | 🔑 **실제로 모델에 닿는 관문.** 2026-09-08에 *«조용한 마이크에서 발화가 모델에 도달조차 못 한다»* 로 낮췄다 |
| 녹음 페이지 · `ingest` | ~~0.006~~ → **0.0025** | 학습기의 «구간 찾기» 값을 그냥 가져왔었다 |
| 첫-항목 게인 경고 | ~~0.015 / peak<0.08~~ → **rms<0.004 **그리고** peak<0.03** | 근거 없이 제일 엄했다 |

🚨 **0.006 은 여기 쓸 값이 아니었다.** 그건 `train_wakeword.py` 가
**통짜 녹음에서 발화 구간을 찾을 때** 쓰는 값이다. 지금은 **슬롯마다 라벨이 있어
구간을 찾을 필요가 없다** — 여기서는 «말을 했나 안 했나»만 가리면 되고,
무음(방 잡음)은 보통 **0.001 아래**다.

### 실측 (2026-09-16, 4명)

| 화자 | 기기 | 발화 RMS(중앙) | 피크 | 런타임 관문 대비 |
|---|---|---|---|---|
| 박성규 | 휴대폰 | 0.0884 | 0.49 | **59배** |
| 황순현 | 헤드셋 | 0.0205 | 0.15 | **14배** |
| 김소영 | 휴대폰 | 0.0088 | 0.07 | **5.9배** |
| 변소윤 | 노트북 | 0.0072 | 0.05 | **4.8배** |

**전 구간 최솟값이 0.0061 로 관문의 4배였다.** 아무도 버릴 이유가 없었다.

> ✅ **이미 받은 것은 전부 쓴다.** 다시 받을 필요 없다.
> ✅ 페이지가 이제 **«소리 잘 들어오고 있어요»** 를 첫 항목 뒤에 보여 준다 —
> 아무 말이 없으면 사람들은 *"작다고 뜨진 않는데 이게 맞나"* 하고 불안해한다.
> 초록 막대가 움직이는 것만으로는 **충분한지**를 알 수 없다.

### 🔑 여기서 배운 것

**«임계를 어디서 가져왔는지»를 안 적으면 그 값이 혼자 걸어 다닌다.**
0.006 은 원래 다른 목적의 값이었는데 세 곳으로 복사되며 근거를 잃었고,
그 위에 내가 근거 없는 10배를 더 얹었다. 세 파일 전부 이제 **«왜 이 값인지»를 주석에 적는다.**

## 3. 🔄 앞으로 어떻게 하나

### 지금 상태

```
4명 / 20~30명   ·   마감 2026-10-06 (그 주에 학교 GPU 학습)
```

### 참가자가 하는 것 — **링크 하나**

> https://pluiz-collect.vercel.app — 이름 · 동의 · 마이크 허용 · 3분 · 「보내기」

설치도 파일 주고받기도 없다. 부탁 문구는 [`teamwork/녹음_부탁드립니다.md`](../teamwork/녹음_부탁드립니다.md) §1 을 복사한다.

> ⚠️ **페이지를 고치면 «새로 여는 사람»부터 최신이다.** 주소(`pluiz-collect.vercel.app`)는
> 항상 최신 배포를 가리키지만, **이미 열어 놓고 녹음 중인 창은 그때 버전**이다.
> 새로고침해야 바뀐다. 지금까지의 변경은 전부 «문구·경고» 수준이라
> **옛 버전으로 보낸 것도 데이터는 똑같이 쓴다.**

### 내가 하는 것 — **주기적으로 가져오기**

알림이 없다. 직접 돌려야 누가 보냈는지 안다.

```bash
cd scripts/collect-server && npm run pull     # 🔁 이미 받은 것은 건너뛴다
cd ../.. && python scripts/ingest_wakeword.py --list      # 몇 명인가
python scripts/inspect_wakeword.py                        # 기기·입력 크기 표
python scripts/inspect_wakeword.py --play <이름>           # 실제로 들어 보기
```

원본은 **`data/wakeword_raw/*.wav`** 에 그대로 있다(16kHz 모노 WAV — 더블클릭하면 재생된다).
`--play` 가 만드는 듣기용 파일은 임시 폴더에 두고 **`data/` 에 남기지 않는다** —
학습 입력과 섞이면 «이게 원본인가 증폭본인가»를 나중에 못 푼다.

### 20~30명이 모이면 (M7 ③ 이후)

| # | 무엇 | 누가 |
|---|---|---|
| 1 | `--holdout 4` 로 **미학습 화자**를 떼어 둔다 (노트북 녹음이 들어가게) | 나 |
| 2 | 평가 하네스로 **현행 기준선** 숫자를 낸다 (FA/시간 · FRR) | 나 |
| 3 | 증강·학습 파이프라인 재작성 — **`negative.npy` 를 실제로 먹이도록** | 나 |
| 4 | 학교 GPU 학습 | 사용자 |
| 5 | 평가 → **되돌림 판단** (FRR 이 현행 80%보다 나쁘면 되돌린다) | 둘 다 |

> 🚨 **3번이 이 수집의 존재 이유다.** 현행 `train_wakeword.py` 는 `--user-audio` 로
> **양성만** 받는다. 지금 `negative.npy` 는 **쌓이기만 하고 안 쓰인다** — 버리지 말 것.
> 그걸 먹이도록 고치는 것이 M7 ④(9/23~)다.
