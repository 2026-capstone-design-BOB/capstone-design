# Pluiz v2 — P1.5 그래프 이관 계획서

> **작성일**: 2026-07-30
> **상태**: 제안 (Proposed) — 사용자 승인 대기 (승인 후 코드 착수)
> **목표**: `create_react_agent` + `run_async`의 손코드 오케스트레이션을
> 명시적 LangGraph StateGraph(`core/graph.py`)로 **이관**. 기능은 불변, 구조만 정리.

---

## 1. 원칙 (Ground Rules)

- **이사(移徙)지 신축이 아님**: 도구·보안·캐시·STT/TTS·UI는 그대로 재사용. 조립 방식만 변경.
- **기능 불변**: 사용자가 보는 동작·응답은 동일해야 함.
- **폴백 유지**: 기존 `core/agent.py`(PluizAgent)는 삭제하지 않고 폴백으로 보존.
- **플래그 전환**: `.env`의 `USE_GRAPH` 플래그로 신/구 코어 선택. 문제 시 즉시 원복.
- **검증 후 승격**: mock 로직 테스트 + Windows 통합 테스트 통과 후에만 기본값을 그래프로.

---

## 2. 로직 이관 매핑 (핵심)

현재 `run_async`/`stream`/`main.py`에 흩어진 로직을 아래처럼 재배치한다.

| # | 현재 로직 (위치) | → 이관 대상 | 비고 |
|---|---|---|---|
| 1 | `check_security()` (main.py 각 엔드포인트) | **input_guard 노드** | 차단 시 사유 응답 후 종료 |
| 2 | 복합명령 감지 → 캐시 스킵 (`_COMPOUND_CMD`) | **fast_path 노드** 내부 | 판단 로직 그대로 이동 |
| 3 | 커맨드 캐시 조회·실행 (`get_cache`) | **fast_path 노드** | 결과를 messages에 기록(P1 반영) |
| 4 | 결정론적 라우터 (`_route_deterministic`) | **fast_path 노드** | 유튜브/지도/폴더/볼륨 등 |
| 5 | LLM 호출 (`create_react_agent`) | **agent 노드** | 그래프 내부 표준 ReAct |
| 6 | 도구 실행 | **tools 노드 (ToolNode)** | agent ⇄ tools 루프 |
| 7 | 타임아웃 (`_ainvoke_with_timeout`) | **그래프 실행 래퍼** | invoke/astream을 wait_for로 |
| 8 | 히스토리 오염 복구 | **실행 래퍼 예외처리** | thread 초기화 후 재시도 |
| 9 | 도구 미호출 재시도 (`RETRY_PROMPT`) | **agent 뒤 조건부 엣지** | 도구 없이 끝나면 재프롬프트 |
| 10 | 빈 응답 복구 / 도구오류 검증(T04) | **output_guard 노드** | 응답 확정·보정 |
| 11 | `session_memory.save` (SQLite 표시용) | **실행 래퍼(호출부)** | 그래프 밖에서 저장 |
| 12 | (신규) 위험명령 승인 | **hitl 노드** | P2에서 구현, 자리만 확보 |

> fast_path가 히트해도 결과를 messages에 남기는 것(P1 핵심)은 그래프에서 기본 동작이 됨.

## 3. 파일 변경 계획

### 신규 / 확장
- `core/graph.py` (확장) — 실 노드 로직 구현: input_guard=`check_security`,
  fast_path=캐시+라우터 통합, output_guard=T04+빈응답복구, agent/tools, retry 엣지.
- `core/graph_agent.py` (신규) — **오케스트레이터** `PluizGraphAgent`.
  기존 `PluizAgent`와 **동일한 공개 API**(`run_async`, `stream`, thread 관리) 제공.
  타임아웃·세션저장·폴백·예외처리는 여기서 래핑.

### 변경 (최소)
- `main.py` — `get_agent()` 대신 플래그로 신/구 선택하는 팩토리 경유.
- `config/settings.py` — `use_graph: bool = False` 추가.
- `.env.example` — `USE_GRAPH=false` 문서화.

### 불변 (그대로)
- `tools/*`, `core/security.py`, `core/command_cache.py`, `services/*`,
  `electron-ui/*`, `memory/session.py`, `core/agent.py`(폴백).

## 5. 리스크 & 완화

- **최고 위험 변경**(코어 실행 경로 교체) → 병행 제작 + 플래그 + 폴백 + 롤백으로 방어.
- **스트리밍(/ws) 의미 변화**: 그래프 `astream`으로 토큰 스트림 재현 필요 → 별도 검증.
- **tool_calls/ToolMessage 무결성**: fast_path는 도구 직접 실행+AIMessage 기록 방식 유지
  (가짜 tool_call 생성 안 함 → "ToolMessage 누락" 오류 회피).
- **재시도·오염복구 회귀**: 기존 케이스를 테스트로 고정 후 이관.
- **Windows 전용 도구**: 로직은 mock으로, 실도구는 Windows 통합 테스트로 분리.

## 6. 완료 기준 (Definition of Done)

1. `USE_GRAPH=true`에서 기존 기능(앱제어·볼륨·검색·파일·캘린더) 동작 동일.
2. 맥락(캐시 후속 지칭), 보안 차단, 캐시/라우터 히트, 재시도, 타임아웃 모두 회귀 통과.
3. `USE_GRAPH=false`로 언제든 기존 코어 즉시 복귀 가능.
4. DEVLOG에 단계별 기록 완료.
