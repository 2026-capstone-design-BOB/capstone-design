# BL-46 — 오프라인이면 **LLM을 아예 부르지 않는다**

## 1. 무엇이 문제인가

사용자(3차 실기): *"밝기 명령이랑 메모장 만들기 명령은 8초 이상 걸린 것 같아."*

```
19:26:51  '메모장 만들어줘'  | 사유=network | 소요 8.02s
19:27:11  '밝기 줄여줘'      | 사유=network | 소요 8.01s
```

**설계대로 동작한 것이다.** [BL-42](../BACKLOG.md)에서 45초 → 8초로 줄였지만,
8초는 **상한**이라 «캐시가 못 잡는 명령»은 **그 8초를 끝까지 태운다.**
인터넷이 끊긴 걸 **턴 시작에 이미 알고 있으면서도** LLM을 부르고 기다린다.

> 🔑 **«덜 나빠졌을 뿐 빨라지지 않았다.»**
> 그리고 이건 오프라인이 *차별점*이어야 하는 프로젝트에서 **가장 나쁜 종류의 지연**이다 —
> 사용자는 «안 되는 것»을 8초 기다린 뒤에 안다.

## 2. 왜 지금까지 못 고쳤나 — 판정과 호출이 다른 층에 있다

```
core/graph_agent.py   ← _offline_now() 가 여기 있다 (바깥)
    └─ self.graph.invoke(...)
         core/graph.py                              (안)
            input_guard → fast_path ─(hit)→ output_guard → END
                               └─(miss)→ agent  ← llm.invoke() 가 여기 있다
```

**오프라인이라는 사실은 바깥에 있고, 그 사실로 막아야 할 호출은 안에 있다.**

⚠️ **바깥에서 그래프를 통째로 건너뛰면 안 된다.** `fast_path`가 **그래프 안에** 있어서,
건너뛰면 **오프라인에서 되던 캐시 명령까지 같이 죽는다.**
⚠️ **바깥에서 `fast_path`를 한 번 더 부르는 것도 안 된다.** 캐시 히트는 도구를
**실제로 실행**하므로 두 번 부르면 **두 번 실행된다**(앱이 두 개 뜨고, 삭제가 두 번 간다).
그리고 [절대규칙 2](../../CLAUDE.md)가 «fast_path 히트를 조기 return으로 최적화하지 말 것»이다 —
캐시 결과도 `state.messages`에 쌓여야 다음 턴 맥락이 이어진다.

## 3. 결정 — **플래그를 그래프 «안»으로 주입한다**

`build_pluiz_graph`에 `is_offline` 하나를 DI로 추가하고, **`agent` 노드가
`llm.invoke()` 직전에** 그것을 본다. 오프라인이면 `OfflineSkip`을 올리고,
바깥이 그것을 받아 **이미 있는 `_dead_end(kind="network")`** 로 보낸다.

```
input_guard → fast_path ─(hit)→ output_guard → END      ← 캐시는 그대로 돈다
                     └─(miss)→ agent
                                 └─ is_offline() ? → raise OfflineSkip
                                                        ↑
                              graph_agent 가 잡아서 _dead_end("network")
```

**왜 이 모양인가:**

| | |
|---|---|
| `fast_path`가 **먼저** 돈다 | 오프라인 캐시 히트는 **하나도 안 잃는다.** 단락은 «캐시가 못 잡은 뒤»에만 걸린다 |
| **예외로 올린다** | `agent`는 `dict`를 돌려주는 노드다. «응답 없음»을 상태로 표현하려면 라우팅·리듀서·`output_guard`를 다 건드려야 한다. 예외는 **한 곳에서 잡히고 한 곳으로 간다** |
| `_dead_end`를 **재사용**한다 | 그 함수가 이미 ① 스레드를 버리고 ② `cache.suggest()`로 제안을 만들고 ③ 제안을 다음 턴까지 들고 있고 ④ `턴 실패 \| 사유=network`를 로그에 남긴다. **새 경로를 만들면 이 넷을 다시 구현해야 하고, BL-39(로그 구멍)가 그렇게 생겼다** |
| DI로 받는다 | 그래프는 이미 `security_check`·`fast_resolve`·`target_exists`를 DI로 받는다. mock이 이 값을 안 주면 **오늘과 똑같이 동작한다**(기본 `None`) |

### 3-1. 🚨 거짓 «오프라인»이 턴을 죽이지 않게 — **한 번 더 확인한다**

이 변경에는 **오늘 없던 위험**이 하나 생긴다.

`_offline_now()`는 **TTL 10초 캐시**다. 지금까지 그 값이 틀려도 손해는
«45초 대신 8초를 기다린다»뿐이었다 — **턴은 그래도 돌았다.**
그런데 이제 그 값이 «LLM을 부를까 말까»를 정한다. **10초 전에 끊겼다가 방금
복구된 경우, 멀쩡한 네트워크에 대고 «인터넷이 없어요»라고 답하게 된다.**

> 🔑 **그래서 단락하기 직전에 «캐시 없이» 한 번 더 찔러 본다**(`ttl=0`).
> 비용은 **오프라인일 때만 0.8초**다 — 온라인이면 캐시된 `False`에서 바로 끝나
> 소켓을 열지 않는다. **틀릴 때만 돈을 낸다.**
>
> 이것은 `_looks_offline()`의 기존 원칙과 같은 방향이다:
> *"판정 실패는 «온라인»으로 읽는다 — 멀쩡한 네트워크에 거짓말을 하는 게 더 나쁘다."*

### 3-2. 건드리지 않는 것

- **「네」 제안 실행** — `_take_suggestion()`은 **그래프를 부르기 전에** 처리된다.
  이 변경의 영향을 받지 않는다(E-09 경로는 그대로다). 확인하고 넣었다.
- **`_timeout()`의 8초 상한** — 남겨 둔다. 단락이 못 잡는 경우
  (턴 도중에 끊김 · 판정이 «온라인»인데 실제로 느림)의 **그물**이다.
  두 장치는 경쟁이 아니라 층이다.
- **승인 대기(HITL) 재개** — `Command(resume)` 경로도 `agent`를 지날 수 있다.
  오프라인이면 단락되어 승인이 버려지는데, **오늘도 같은 결과**다(8초 뒤에 그렇게 된다).
  달라지는 것은 **속도뿐**이다.

## 4. 버린 대안

| 대안 | 왜 안 했나 |
|---|---|
| **바깥에서 그래프를 통째로 건너뛴다** | `fast_path`가 안에 있어 **오프라인 캐시 명령이 같이 죽는다.** 이 기능의 전부를 잃는다 |
| **바깥에서 `fast_path`를 먼저 한 번 부른다** | 캐시 히트가 **도구를 두 번 실행**한다. 되돌릴 수 없는 도구가 섞이면 사고다 |
| **`agent` 노드가 오프라인 응답 문자열을 직접 만든다** | `_dead_end`의 넷(스레드 버리기·제안·제안 보관·로그)을 **그래프 안에 다시 구현**하게 된다. 한쪽만 고쳐지는 구조 — 이 저장소가 BL-29·BL-41에서 두 번 겪은 모양이다 |
| **상한을 3초로 깎는다** | BL-47 전에는 밝기 캐시 히트가 5~6초여서 **멀쩡한 명령을 죽였다.** BL-47을 고쳐 그 제약은 풀렸지만, 그래도 **«기다리는 시간을 줄이는 것»이지 «안 기다리는 것»이 아니다** |

## 5. 실측

| | 전 | 후 |
|---|---|---|
| 오프라인 · 캐시가 못 잡는 명령 | **8.0초** | **≈0.8초** (확인 probe 한 번) |
| 오프라인 · 캐시 히트 | 그대로 (0.02 ~ 1.1초) | **그대로** |
| 온라인 | 그대로 | **그대로** (소켓을 안 연다) |

## 6. 이 결정이 틀렸다고 판정될 조건

- **온라인인데 «인터넷이 없어요»가 나온다** → 3-1의 재확인이 부족한 것이다.
  그때는 단락을 끄고(`is_offline=None`) 8초 상한만 남기면 **오늘로 되돌아간다.**
  ⚠️ **되돌리는 비용이 한 줄이라는 것이 이 설계를 고른 이유 중 하나다.**
- **오프라인에서 캐시 명령이 안 돈다** → `fast_path`보다 앞에서 단락이 걸린 것이다.
  회귀 테스트가 이 방향을 고정한다(§7).

## 7. 테스트가 고정하는 것 (`tests/test_offline_skip.py`)

**양방향이다.** 한쪽만 두면 회귀를 놓친다.

1. 오프라인 + 캐시 미스 → **LLM을 한 번도 안 부른다**(호출 카운터 0)
2. 오프라인 + **캐시 히트** → **평소대로 실행된다**(단락이 캐시를 안 먹는다)
3. **온라인** → LLM을 부른다(단락이 안 걸린다)
4. `is_offline` 미주입(mock 기본) → **오늘과 동일**
5. 거짓 양성 방지 — 캐시가 «오프라인»이라고 해도 **재확인이 «온라인»이면 LLM을 부른다**
