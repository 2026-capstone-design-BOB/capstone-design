# 실기 — 내가 할 것만 (2026-10-01 · 웨이크워드)

이 문서만 보고 하면 됩니다. 순서대로 하시면 됩니다.
결과는 `성공 / 실패 / 애매` 중 하나에 표시하고, 할 말은 메모에 적어 주세요.

전체 약 20분. 그중 10분은 기다리는 시간이라 그 동안 딴 일 하시면 됩니다.

---

## 무엇이 바뀌었나 (읽고 시작하세요)

호출어 판정을 **두 군데** 바꿨습니다.

| | 전 | 후 |
|---|---|---|
| 모델 | 9/28 학습본 | **10/01 재학습본** |
| 깨는 조건 | 한 번 들리면 바로 | **연속 두 번** 들려야 |
| 임계 | 0.62 | **0.80** |

숫자로는 이렇게 나왔습니다.

| | 전 | 후 |
|---|---:|---:|
| 안 불렀는데 혼자 깨는 것 | 시간당 **264회** | 시간당 **15회** |
| 불렀는데 놓치는 것 | 12.7% | **15.2%** |
| 깨는 데 걸리는 시간 | 바로 | **0.6초 뒤** |

**숫자로 못 아는 게 둘입니다. 그게 오늘 보실 것입니다.**

- 0.6초 늦게 깨는 것이 **답답한가**
- 일곱 번에 한 번 놓치는 것이 **짜증나는가**

> 🚨 숫자가 좋아져도 쓰기 싫으면 되돌립니다. 설정 두 줄이면 됩니다.
> 그 판단을 하려고 하는 실기입니다.

---

## 0. 시작 전에

**서버와 UI 를 둘 다 다시 띄워야 합니다.** 모델과 설정이 둘 다 바뀌었습니다.

```
launch.bat
```

**켜고 나서 알려 주세요.** 로그에 표시를 해 둬야 이번 것만 셀 수 있습니다.

---

## 1. 가까이서 부르기 — 10번 (2분)

### 할 것

평소 앉는 자리(30cm쯤)에서 **"플루이즈"** 를 **정확히 10번** 부릅니다.
한 번 부르고 **5초 쉬고** 다음 번.

🔑 **이번엔 깬 뒤의 느낌도 봐 주세요.** 예전보다 0.6초 늦게 깹니다.

### 적어 주실 것

```
부른 횟수:  10 번

체감상 몇 번 깼나:
→

🔑 0.6초 늦는 게 느껴지나 / 답답한가:
→

결과:  성공 / 실패 / 애매
메모:
```

> 9/30에는 10/10이었습니다. 이번엔 **8~9번이면 예상대로**입니다(놓침 15%).
> 그보다 적으면 알려 주세요 — 되돌릴 근거가 됩니다.

---

## 2. 떨어져서 부르기 — 1m 5번, 2m 5번 (3분)

9/30에 둘 다 5/5였습니다. **임계를 올렸으니 여기가 나빠졌을 수 있습니다.**
나빠졌다면 그게 가장 중요한 신호입니다 — 부스에서는 떨어져서 부르니까요.

### 할 것

1. **1m** 에서 "플루이즈" **5번** (5초 간격)
2. **2m** 에서 "플루이즈" **5번** (5초 간격)

목소리 크기는 평소대로. 일부러 크게 하지 마세요.

### 적어 주실 것

```
1m — 부른 횟수: 5 번 / 체감상 깬 횟수:
2m — 부른 횟수: 5 번 / 체감상 깬 횟수:

9/30(둘 다 5/5)보다 나빠졌나:
→

결과:  성공 / 실패 / 애매
메모:
```

---

## 3. 가만히 두면 혼자 깨나 (10분 — 걸어두고 딴 일)

**여기가 이번에 고친 바로 그 자리입니다.**

### 할 것

마이크를 켜 둔 채 **10분 동안 평소처럼** 컴퓨터를 쓰세요.
유튜브, 문서 작업, 통화, 혼잣말 — 뭐든 됩니다. **부르지만 마세요.**

조용할 필요 없습니다. 오히려 평소처럼 소리가 나는 게 좋습니다.

### 적어 주실 것

```
10분 동안 뭘 하고 있었나:
→

혼자 깨는 걸 눈치챘나 / 몇 번쯤:
→

결과:  성공 / 실패 / 애매
메모:
```

> **9/30에는 10분에 34번이었습니다.** 이번엔 **2~3번이면 예상대로**입니다.
> 10번을 넘으면 알려 주세요 — 측정과 실제가 다르다는 뜻입니다.

---

## 4. 시끄러울 때 부르기 — 5번 (2분)

9/30에 2/5로 실패했던 항목입니다. 나아졌는지 봅니다.

### 할 것

유튜브나 음악을 **평소 볼륨으로** 틀어 놓고, 가까이서 "플루이즈" **5번**.

### 적어 주실 것

```
뭘 틀어놨나:
→

부른 횟수: 5 번 / 체감상 깬 횟수:

내 말에 깬 건지 영상 소리에 깬 건지 구분되나:
→

결과:  성공 / 실패 / 애매
메모:
```

## 5. 깨고 나서 멀쩡한가 (2분)

깨는 것만 고쳤으니 **그 다음이 그대로인지** 한 번만 봅니다.

### 할 것

> **"플루이즈"** → 깨면 → **"지금 몇 시야"**

두세 번 해 보세요.

### 적어 주실 것

```
깬 뒤에 말이 제대로 들어가나:
→

답이 제대로 오나:
→

결과:  성공 / 실패 / 애매
메모:
```

## 6. 🔴 가장 중요한 질문 — 쓰시겠습니까?

숫자가 아니라 **느낌**을 적어 주세요. 이게 되돌릴지 말지를 정합니다.

```
전보다 나아졌다고 느껴지나:
→

0.6초 지연 — 참을 만한가, 거슬리는가:
→

놓치는 것 — 한 번 더 부르면 되니 괜찮은가, 짜증나는가:
→

🔴 전시회 부스에서 이대로 쓰시겠습니까?
   (아니면 버튼·단축키로 말 거는 쪽이 낫겠습니까?)
→
```

> **마지막 줄이 오늘의 핵심입니다.** 부스는 관람객이 계속 떠드는 자리인데,
> 지금 임계로 못 막는 조건이 하필 **「남의 말소리」** 입니다.
> 버튼으로 가면 혼자 깨는 일이 **구조적으로 0** 이 되고, 호출어는
> *"이것도 됩니다"* 로 보여 주면 됩니다. **제품 결정이라 정해 주셔야 합니다.**

```
python scripts/count_wake.py <표시한 줄 번호>
```

그게 없으면 놓침률의 분모가 없습니다.
