### 🚨 결함 ① — 바탕화면을 «탐색기 창»으로 집었다 (**고침**)

`explorer.exe` 는 파일 탐색기만이 아니라 **바탕화면(`Progman`)과 작업표시줄**도 띄운다.
창 목록에서 **먼저 걸리는 것이 바탕화면**이었고, 바탕화면은 `IsZoomed` 가 **원래 True** 라
— 오늘 넣은 되묻기가 **엉뚱한 창에 대해 정확히 확인하고 ✓ 를 줬다.**
**검증이 거짓말을 인증한 셈이다.**

→ `_is_real_window()` 한 자리에서 셸 창을 거른다(열기·포커스·캡처가 전부 그 함수를 지난다).
실측 확인: `탐색기` → 이제 `'testing - 파일 탐색기'`(`CabinetWClass`) 를 집는다.

### 🚨 결함 ② — **서버에서는 밝기·볼륨을 한 번도 못 읽고 있었다** (**고침**)

로그가 원인을 **이름으로** 말해 줬다:

```
x_wmi_uninitialised_thread: … you're probably running inside a thread
without first calling pythoncom.CoInitialize[Ex]
```

그래프는 도구를 **워커 스레드**에서 돌리는데(`asyncio.to_thread`), **COM 은 스레드마다
켜야 한다.** 메인 스레드에서만 자동으로 켜져 있었다 — 그래서 **진단 스크립트에서는
읽히고 서버에서는 -1** 이었다.

🔑 **[BL-47](../BACKLOG.md)의 안 착륙한 절반이다.** `wmi` 를 깔아 «읽을 수 있는 PC»가
됐다고 적었는데 **제품 경로에서는 여전히 못 읽었다.** 그래서 밝기가 계속 기억값으로
돌았고, 손으로 30%로 내려도 우리는 60이라고 믿었다(⑤의 «계속 60이라고 함»이 이것이다).

→ `_ensure_com()` 을 읽기·쓰기 앞에 둔다(스레드당 한 번). 실측: 워커 스레드에서 **밝기 40 · 볼륨 40**.

### ⏸️ 결함 ③ — **«밝기 알려줘»가 밝기를 바꾼다** (안 고쳤다 → [BL-60](../BACKLOG.md))

로그: `입력='밝기 알려줘' | 실행=['캐시'] | 응답 43자`.
**캐시가 조회 발화를 조작 명령으로 맞췄다.** 그래서 «알려줘»에 밝기가 70%로 올라갔다.

그리고 **읽어 주는 도구가 아예 없다** — `brightness_up/down` · `set_volume` 뿐이라

### 🚨 ① LLM 이 **도구 결과를 지어냈다** → [BL-61](../BACKLOG.md) (같은 날 고침)

```
🎤 밝기 80% 해 줘        🤖 ✓ 밝기: 40% → 80%        ← 도구를 안 불렀다
🎤 지금 밝기 알려줘      🤖 ✓ 현재 밝기는 80%입니다.  ← 기기를 읽은 적이 없다
```

로그: 두 턴 다 **`요청=없음 | 실행=없음 | 사유=잡담`**.
실제 밝기가 40%인 채로 «80%입니다» 를 **세 번** 들었다.
→ `✓` 는 **도구만 쓸 수 있는 표시**다. «도구 0개 + `✓` 로 시작» 을 그물로 막았다.

### 🔴 ② **«밝기 80%» 를 할 수가 없다** → [BL-60](../BACKLOG.md)

(볼륨엔 `set_volume` 이 있는데 밝기엔 없다). 그래서 LLM 이 **할 수 있는 척**했다.
읽는 도구(`get_brightness`·`get_volume`)도 없다 — 둘 다 BL-60에 묶었다.

로그에 `ModuleNotFoundError: No module named 'pycaw'` 가 **2회차에도** 찍혔다.
`launch.bat` 은 `python` 을 그냥 부른다 — **`conda activate pluiz` 를 한 창에서**
띄워야 오늘 깐 모듈이 보인다. 그래서 ⑥의 «읽지 못해» 문구는 **결함이 아니라 환경**이다.

```bash
conda activate pluiz
python main.py          # 또는 그 창에서 launch.bat
```
