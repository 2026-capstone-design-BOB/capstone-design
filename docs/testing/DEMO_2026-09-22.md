### §0-A-1 🔑 **무엇이 갈랐는지는 로그가 답했다 — 화면이 아니라 `window` 인자다**

```
2026-09-12   UI 요소 탐색 (설정)     target='블루투스'      → ✅ 찾음 (335,410)
2026-09-14   UI 요소 탐색 (설정)     target='비행기 모드'   → ❌ 못 찾음(다른 페이지에 있다)
2026-09-20   UI 요소 탐색 (전체화면) target='블루투스'      → 🔴 문서의 글자를 짚었다
```

`point_at_element` 는 `window` 가 **비면 전체 화면**을 뒤진다. LLM 이 `window="설정"` 을
채우면 `ensure_visible` 이 **설정을 띄우고** 거기서만 찾는다 — *"설정이 열리고"* 가 그것이다.
🚨 **LLM 이 채울지 말지는 매번 같지 않다.** 그래서:

| LLM 이 | 화면이 더러우면 | **정리 + 설정을 띄워 두면** |
|---|---|---|
| `window="설정"` | ✅ 정상 | ✅ 정상 |
| `window=""` | 🔴 **엉뚱한 글자를 자신 있게 짚는다** | ✅ 설정에서 찾는다 |

🔑 **그래서 «3번(설정을 미리 띄운다)»이 이 우회의 핵심이다.** 문서만 닫으면 **최악**
(틀린 곳을 자신 있게 짚기)은 사라지지만, `window=""` 일 때 *"못 찾았어요"* 가 남는다.

### §0-A-2 ✅ **그런데 같은 날 고쳤다 — 우회가 아니라 수선이 있다**

> 🔑 **사용자 지적이 방향을 바꿨다** — *"바탕화면에서 블루투스 어디서 키는지 모르면
> **처음부터 알려주는 게 맞지 않나**"*. 맞다. **«설정을 미리 띄워 둔다»는 이 기능이
> 존재하는 이유인 그 상황을 없애서 통과시키는 것**이고,
> 🚨 **교수님이 *"설정 닫고 해 보세요"* 하면 그 자리에서 깨진다.**

`resolve_search_window()` 를 넣어 **설정 안의 것이면 범위를 「설정」으로 정한다**
([BL-64](../BACKLOG.md) · [테스트 73건](../../tests/test_bl64_settings_scope.py) · 양방향).
**바탕화면에서 물어도 설정을 열고 짚고**, *"설정이 꺼져 있어서 먼저 열었어요"* 라고 **말한다.**

| | 우회(§0-A 1~3) | **수선(BL-64)** |
|---|---|---|
| 바탕화면에서 물으면 | ⚠️ 설정을 미리 띄워 둬야 산다 | ✅ **알아서 열고 짚는다** |
| «설정 닫고 해 보세요» | 🔴 **깨진다** | ✅ 된다 |
| 5장면 멘트 | ⏸️ «열고»를 빼야 한다 | ✅ **그대로 쓴다** |
| 코드 | 0줄 | `tools/vision.py` (동결 예외가 필요하다) |

> ### ✅ **2026-09-20 — 시연에 넣었다** (사용자 결정 · 태그를 옮겼다)
