1한 문장으로

“메모장 열어줘” 처럼 말하면, 그 말을 알아듣고 실제로 Windows를 조작합니다. 챗봇이 «이렇게 하세요»라고 알려 주는 것이 아니라 직접 합니다.

호출어(“플루이즈”)·🎙️ 버튼·단축키 중 아무거나로 깨우고, 말하고, 결과를 듣습니다.

3어떻게 도는가

①깨어난다 — 호출어 · 🎙️ 버튼 · 단축키. 창은 안 뜨고 접힌 채로 듣습니다
②알아듣는다 — 녹음을 글자로(STT). 말이 끝났는지를 크기와 «사람 말인가» 두 가지로 판단해서 끊습니다
③정한다 — 자주 쓰는 말이면 캐시가 바로(0.09초 (AI는 9.25초)) 답하고, 처음 보는 말이면 AI가 어떤 기능을 쓸지 고릅니다
④되돌릴 수 없는 일이면 먼저 묻습니다 — 7개만 물어봅니다 (파일·폴더 삭제 · 화면 클릭 · 앱 강제 종료 · 덮어쓰기 · 파일 이동 · 이름 변경)
⑤한다, 그리고 확인한다 — 실제로 됐는지 보고, 안 됐으면 안 됐다고 말합니다

4남들과 다른 점

직접 한다알려 주는 것이 아니라 실행합니다. 그래서 «되돌릴 수 있나»가 설계의 중심입니다
정직하게 말한다못 한 것을 했다고 하지 않습니다. 도구를 안 불렀는데 «✓ 했어요»라고 말하는 길을 코드가 막습니다
인터넷이 끊겨도자주 쓰는 명령은 65.0% (컴퓨터 안 기능만 100%) 돕니다 — ⚠️ 차별점이라고 말하지 않습니다(윈도우 음성 액세스도 오프라인입니다)
부르는 길이 셋버튼 · 단축키 · 호출어 셋 다. 시끄러운 곳에서는 버튼이 확실합니다 — 약점이 아니라 선택입니다

7어기면 깨지는 것 11가지

개발할 때 지키는 규칙입니다. 배경은 CLAUDE.md 에.

  • 그래프 노드를 async로 바꾸지 말 것
  • `fast_path` 히트를 조기 return으로 "최적화"하지 말 것
  • 히스토리를 슬라이스로 자르지 말 것
  • `.env` 변경 후 `get_settings.cache_clear()`
  • `services/`·`electron-ui/`를 `src/` 같은 폴더로 감싸지 말 것
  • "이번 턴"을 판단할 땐 `current_turn_messages()`를 쓸 것
  • 테스트에서 소스를 열 땐 `encoding="utf-8"`를 붙일 것
  • `/voice`의 `thread_id`·`use_tts`에서 `Form(...)`을 빼지 말 것
  • 클릭 도구에 좌표 인자(`x`, `y`)를 추가하지 말 것
  • `main.py`의 `allow_origins=["null"]`과 OPTIONS 면제를 "정리"하지 말 것
  • 계획 상태(`plan`/`plan_cursor`)를 턴 너머로 새게 하지 말 것
