# 🤖 Claude Code 가 읽는 부분 — 아래는 지시입니다

**팀원(개발자가 아님)을 돕고 있습니다.** 아래 규칙과 절차를 따르세요.

## 0. 🚨 매번 먼저 — 최신으로 맞춘다

이 프로젝트는 **거의 매일 바뀝니다.** 낡은 자료로 포스터를 쓰면 틀린 숫자가
인쇄됩니다. 그래서 **어떤 주문이든 이것부터** 합니다.

```bash
git pull
```

| 결과 | 할 것 |
|---|---|
| 새 커밋을 받았다 | **무엇이 바뀌었는지 한두 줄로 알려 준다** (`git log --oneline` 으로 받은 범위만) |
| `Already up to date` | 그냥 넘어간다. 굳이 말하지 않는다 |
| 🚨 충돌이 났다 / 로컬 변경이 있다 | **직접 해결하지 말 것.** 어떤 파일인지 보여 주고 *"변소윤에게 물어보세요"* 라고 안내한다 |

🚨 **`git commit` · `git push` 를 하지 않습니다.** 이 PC 는 보고 정리하는 곳입니다.
만든 결과물은 **파일로 변소윤에게 전달**합니다 → [00_시작하기 §6](00_시작하기.md)

## 1. 규칙 — 어기면 작업이 버려집니다

| | 규칙 | 왜 |
|---|---|---|
| ① | **`docs/` 밖의 파일을 고치지 않는다** | `core/`·`tools/`·`services/`·`electron-ui/` 는 프로그램 코드입니다 |
| ② | 🚨 **숫자를 지어내지 않는다** | *"응답 3초"* 는 **잰 사람만** 쓸 수 있습니다. 아래 §2 의 출처에서만 가져옵니다 |
| ③ | **출처를 적는다** | 어느 문서에서 가져왔는지. 조사한 것은 URL |
| ④ | **모르면 비워 두고 표시한다** | `⬜ 확인 필요: (무엇이 궁금한지)`. **그럴듯하게 채운 칸이 제일 위험합니다** |

> 🚨 ②와 ④는 **당신(Claude)에게도 그대로 적용됩니다.** 문서에서 못 찾은 숫자를
> 추정해서 쓰지 마세요. 못 찾았으면 «못 찾았다»고 말하는 것이 정확합니다.
