# 과제 D · 학과 산출물을 양식(hwp)으로 옮기기

> **담당: 박세민** · 2026-09-30 배정 · **3차에 나눠서** 합니다
> 
> 🔑 **새로 쓰는 일이 아닙니다. 이미 쓰여 있는 것을 학교 양식에 옮기는 일입니다.
> 
> 내가 한 번 쭉 읽어보니까 이 AI녀석이 되게 깐깐하게 써 놨는데 언니 판단 하에 적당히 작성할 수 있는 내용이나 여기 문서에 틀린 내용이 있으면 언니가 고쳐서 써줘**

## 1. 무슨 일인가줘

학과에 낼 산출물이 **8종**입니다. 내용은 이미 **md 파일로 다 쓰여 있습니다.**
양식 hwp는 비어 있고, **md 내용을 그 양식에 옮기는 것**이 이 과제입니다.

```
docs/documentations/작업본/D01_시스템정의서.md      ← 내용 (이미 있음)
docs/documentations/2025-개정-D01-시스템정의서.hwp  ← 양식 (비어 있음)
                                                      ↑ 여기로 옮긴다
```

> 🚨 **왜 지금까지 md로만 있었나** — hwp는 편집기를 붙들고 있어야 해서 개발과 병행이
> 안 됩니다. 그래서 **내용은 md에서 관리하고 제출 직전에 한 번만 옮기기로** 정해 뒀습니다.
> → [작업본 README](../documentations/작업본/README.md)

---

## 2. 🚨 절대 원칙 — **내용을 새로 쓰지 않습니다**

| 하는 것                                 | 하지 않는 것              |
| ------------------------------------ | -------------------- |
| md에 적힌 문장을 hwp 표에 **옮긴다**            | 문장을 **다시 쓴다**        |
| 양식이 요구하는 **형식**(폰트·번호·목차)을 맞춘다       | 빠진 내용을 **채워 넣는다**    |
| `⬜ TODO(확인)` 칸을 **그대로 두고 목록으로 보고**한다 | 모르는 칸을 **그럴듯하게 메운다** |

> 🔑 **md가 원본이 아닙니다. md도 파생 문서입니다.**
> D04·D05·D06·D07의 진짜 원본은 `docs/BACKLOG.md` · `docs/DEVLOG.md` · 코드 · `tests/` 입니다.
> 그래서 **hwp에서 내용을 고치면 세 곳이 어긋납니다.** 고칠 것이 보이면 **고치지 말고 알려** 주세요.
> 
> 이 저장소는 «같은 사실이 두 곳에 있으면 한쪽만 갱신돼 어긋난다»로 여러 번 사고가 났습니다.

## 4. 시작하는 법

### 4-1. 파일 받기

[00_시작하기.md](00_시작하기.md) 의 2번을 그대로 따라 합니다.
**브랜치는 `dev/post-demo`** 입니다 — `main` 이 아닙니다.

받은 뒤 이 두 폴더가 보이면 성공입니다.

```
docs/documentations/          ← 양식 hwp 8개
docs/documentations/작업본/    ← 내용 md 8개
```

### 4-2. 작업 순서 (문서 하나당)

1. 작업본 md를 **끝까지 읽습니다** — 옮기기 전에 무슨 내용인지 알아야 합니다
2. 양식 hwp를 열고 **가이드라인 페이지를 삭제**합니다 (양식이 그렇게 지시합니다)
3. md 내용을 해당 표·절에 옮깁니다
4. 형식을 맞춥니다 (아래 4-3)
5. `⬜ TODO(확인)` 를 만나면 **비워 두고 목록에 적습니다**
6. 문서번호를 부여합니다 — `20__-TeamName-Doc-0__`

### 4-3. 형식 규칙 (8종 공통)

| 항목              | 값                               |
| --------------- | ------------------------------- |
| 글꼴              | **맑은고딕**                        |
| 제목1 / 2 / 3 / 4 | 20pt / 14pt / 12pt / 11pt       |
| 본문              | 10pt                            |
| 줄간격             | **150%** (단, D05·D06은 **130%**) |
| 목차              | 11pt · 160%                     |
| 페이지 번호          | **필수**                          |

🚨 **목차는 절대 수정하지 않습니다.** 해당 내용이 없는 절은 **삭제하지 말고 「해당 없음」** 이라고 적습니다.

### 4-4. 문체 규칙 (양식이 요구합니다)

- **모호한 표현 금지** — *"~할 수도 있다"* 를 쓰지 않습니다
- 모든 문장에 **주어·동사·목적어**가 있어야 합니다
  - ❌ *"데이터를 입력받아야 한다"*
  - ✅ *"사용자가 음성으로 명령을 입력한다"*
- **개조식**으로 짧게 끊어 씁니다
- 표·그림에 **번호**를 붙이고 본문에서 인용합니다

> md 본문은 이미 이 규칙에 맞춰 쓰여 있습니다. **옮기기만 하면 대체로 맞습니다.**

## 5. ⬜ 못 채우는 칸 — **지어내지 말고 모아서 보고**

md에 `⬜ TODO(확인)` 로 표시된 칸은 **변소윤도 모르는 것**입니다. 대부분 학과에 물어봐야 합니다.

| 무엇               | 어디에 쓰이나                     |
| ---------------- | --------------------------- |
| 팀 번호             | 모든 문서 · 제출 파일명              |
| 프로젝트 유형 (분류 기준)  | D01 · 작품 소개글                |
| 지도교수님 성함         | D01 · D08                   |
| 학과명 (정확한 명칭)     | 전 문서                        |
| **참여학생 학번**      | D01 · D08 — 🚨 아래 참조        |
| 개발 시작일           | D02                         |
| **산출물 8종 제출 기한** | 🔴 **아직 모릅니다.** 10월 중순~말 추정 |
| 그림 2~3장 (구성도·화면) | D06 · D08 — **변소윤이 만듭니다**   |

### 🚨 학번은 md에 적지 않습니다

이 저장소는 **공개**입니다. 학번은 개인정보라 **md에 넣지 않고 hwp에서만 채웁니다.**
→ [학번_공개노출_대응.md](학번_공개노출_대응.md)

## 6. ✅ 검수 기준 — 문서 하나를 끝낼 때마다

- [ ] 가이드라인 페이지를 **삭제**했다
- [ ] 목차를 **하나도 안 바꿨다** (없는 절은 「해당 없음」)
- [ ] 글꼴·크기·줄간격이 4-3 표와 같다
- [ ] 페이지 번호가 있다
- [ ] 문서번호를 넣었다
- [ ] **md에 없는 문장을 새로 쓰지 않았다**
- [ ] 못 채운 칸을 **목록으로 정리**했다 (지어내지 않았다)
- [ ] 표·그림에 번호가 있고 본문에서 인용한다
