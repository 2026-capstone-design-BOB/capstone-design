# 12 · 용어 사전 — 개발자가 쓰는 말 풀이

> 회의·문서·발표 준비에서 나오는 말들입니다. **전공 지식 없이 읽을 수 있게** 적었습니다.
> 여기 있는 설명은 **그대로 포스터·소개글에 써도 되는 수준**으로 다듬어 뒀습니다.

---

## 1. 이 프로젝트의 뼈대

| 말 | 뜻 | 한 줄로 설명하면 |
|---|---|---|
| **에이전트 (agent)** | 목표를 받아서 **스스로 여러 단계를 실행하는** AI | 질문에 답만 하는 게 아니라 **실제로 뭔가를 하는** AI입니다 |
| **LLM** | 대규모 언어 모델. ChatGPT·Gemini 같은 것 | 말을 이해하고 만드는 AI. 우리는 Google의 **Gemini**를 씁니다 |
| **도구 (tool)** | AI가 실제로 실행할 수 있는 기능 하나 | "메모장 열기", "파일 지우기" 같은 것. 우리는 **44개** 있습니다 |
| **LangGraph** | AI의 작업 흐름을 그림처럼 짜는 도구 | "먼저 위험한지 검사 → 계획 → 실행 → 확인" 순서를 고정해 둡니다 |
| **오버레이 UI** | 화면 위에 항상 떠 있는 작은 창 | 알약 모양으로 구석에 떠 있는 그것입니다 |

---

## 2. 우리가 만든 기능 이름

| 말 | 뜻 |
|---|---|
| **웨이크워드 (호출어)** | "플루이즈"라고 부르면 깨어나게 하는 기능. 일명 "헤이 시리"의 그것 |
| **STT** | Speech To Text. **말 → 글자**. 사용자가 한 말을 컴퓨터가 알아듣는 단계 |
| **TTS** | Text To Speech. **글자 → 말**. 프로그램이 소리 내어 답하는 단계 |
| **캐시** | 자주 쓰는 명령을 저장해 뒀다가 **AI를 안 부르고** 바로 실행하는 장치 |
| **비전 (Vision)** | 화면을 사진으로 찍어 AI에게 보여주고 **무엇이 보이는지** 알아내는 기능 |
| **포인팅** | 화면에서 찾은 자리에 **동그라미를 그려 짚어 주는** 기능 |
| **승인 (HITL)** | 되돌릴 수 없는 일 전에 **"할까요?"라고 물어보는** 단계. Human In The Loop |
| **계획 수립 (Plan)** | 복합 명령("메모장 켜고 저장해줘")을 **단계로 나눠** 순서대로 실행하는 것 |
| **오프라인 모드** | 인터넷이 없을 때도 되는 부분 |

## 3. 숫자를 말할 때 나오는 말

| 말 | 뜻 | 낮아야 좋나 높아야 좋나 |
|---|---|---|
| **FRR · 놓침률** | 불렀는데 **안 깨어난** 비율 | 🔽 낮을수록 좋음 |
| **FA · 오탐** | 안 불렀는데 **혼자 깨어난** 횟수 | 🔽 낮을수록 좋음 |
| **히트율** | 캐시가 AI 없이 답한 비율 | 🔼 높을수록 좋음 (단, 아래 주의) |
| **환각 (hallucination)** | AI가 **사실이 아닌 것을 지어내는** 것 | 🔽 낮을수록 좋음 |
| **정확도 (accuracy)** | 시킨 대로 맞게 했는지 | 🔼 |
| **커버리지** | 전체 중에서 **되는 것의 비율** | 🔼 |

> ⚠️ **"히트율이 높으면 무조건 좋다"가 아닙니다.** 엉뚱한 명령에 잘못 맞아도 히트율은 올라갑니다.
> 그래서 11월에 **오매칭률**(잘못 맞은 비율)을 같이 잽니다. 발표에서 히트율만 말하면
> "그게 맞는 답이었는지는 어떻게 아나요?"에 막힙니다.

## 4. 개발 과정에서 나오는 말

| 말 | 뜻 |
|---|---|
| **저장소 / 리포지토리** | 코드와 문서가 모여 있는 곳. 우리는 GitHub에 있습니다 |
| **커밋** | 변경한 내용을 기록으로 남기는 것 |
| **푸시** | 내 컴퓨터의 기록을 GitHub에 올리는 것. **올려야 남이 볼 수 있습니다** |
| **브랜치** | 작업을 갈라 두는 것. 완성되면 합칩니다(병합) |
| **BL-숫자** | 백로그 항목 번호. **발견된 문제 하나**에 붙는 번호입니다 (예: BL-67) |
| **기능 동결** | 이 날 이후로는 코드를 안 고친다고 정한 날. **10/31** |
| **회귀 (regression)** | 고쳤던 게 **다시 망가지는** 것 |
| **mock 테스트** | 가짜 환경에서 도는 자동 검사. 빠르지만 **"실제로 된다"를 보증하지는 않습니다** |
| **실기 검증** | 사람이 **진짜로 돌려 보고** 확인하는 것 |
| **ADR / 설계 문서** | "왜 이렇게 만들기로 했나"를 적어 둔 문서 |

## 5. 문서 이름이 무슨 뜻인가

개발 쪽 문서 이름이 회의에서 나올 때가 있습니다. **당신이 직접 읽을 필요는 없습니다.**

| 문서 | 무엇이 들어 있나 |
|---|---|
| `DEVLOG.md` | 개발 일지. 날짜별로 무엇을 했는지 |
| `BACKLOG.md` | 발견된 문제 목록 (BL-숫자) |
| `ROADMAP.md` | 학기 단위 목표 |
| `TASKS.md` | 지금 하는 중인 작업 체크리스트 |
| `ARCHITECTURE.md` | 시스템이 어떻게 도는지 |

> 💡 이 중에 **당신에게 필요한 내용은 전부 [10_개발_현황.md](10_개발_현황.md)와
> [11_어필_재료.md](11_어필_재료.md)로 옮겨져 옵니다.** 위 문서들을 직접 열 일은 없습니다.
