# 01 · 우리가 만들고 있는 것

> 프로젝트에 처음 합류한 사람을 위한 설명입니다.
> **포스터·소개글·발표자료를 쓰려면 이 문서의 내용을 알아야 합니다.**
> 개발 지식은 필요 없습니다.

---

## 1. 한 줄로

**Pluiz(플루이즈)** — 한국어 음성 명령으로 Windows PC를 제어하는 AI 에이전트.

---

## 2. 무엇을 하는 프로그램인가

컴퓨터 화면 구석에 **작은 알약 모양 창**이 항상 떠 있습니다.
사용자가 **"플루이즈"** 라고 부르거나 마이크 버튼을 누른 뒤 명령을 말하면, 그대로 실행됩니다.

**실제 동작 예시** (9월 시연 대본 9장면입니다 — 포스터·발표에 그대로 쓸 수 있습니다)

| 사용자가 말하는 것 | 프로그램이 하는 일 |
|---|---|
| "플루이즈" → "메모장 켜줘" | 메모장이 실행됩니다 |
| "그거 꺼줘" | **방금 켠 메모장**을 끕니다 (앞의 대화를 기억합니다) |
| "메모장 켜줘" (또 한 번) | 이번엔 **AI를 거치지 않고 즉시** 실행합니다 (한 번 배웠기 때문) |
| "지금 화면에 뭐 있어?" | 화면을 보고 무엇이 떠 있는지 설명합니다 |
| "블루투스 어디서 켜?" | 설정 화면을 **열고**, 해당 항목 위치를 **화면에 동그라미로 표시**합니다 |
| "a.txt 지워줘" | **"a.txt를 삭제할까요?" 라고 먼저 묻고**, "응" 하면 지웁니다 |
| "메모장 열고 b.txt도 지워줘" | 두 가지 일을 **순서대로** 처리합니다 |
| (설정) 내보내기 → 가져오기 | 학습한 내용을 파일 하나로 옮깁니다 |
| "오류 뜨면 알려줘" | 화면을 지켜보다가 변화가 생기면 알려 줍니다 |

## 3. 왜 만들었나 — 발표에서 제일 먼저 받는 질문

> *"이미 Siri나 Bixby 같은 게 있는데 왜 굳이?"*

**우리 답변은 "더 낫다"가 아니라 "상용이 하지 않는 자리를 공략했다"입니다.**

| | 기존 음성 비서 | Pluiz |
|---|---|---|
| 주 무대 | 스마트폰 | **Windows PC** |
| PC 제어 범위 | 앱 실행 정도 | 창 제어 · 파일 · 밝기 · 볼륨 · 키보드 입력까지 |
| 인터넷 | 필수 | **없어도 핵심 기능 동작** |
| 위험한 동작 | 그냥 실행 | **반드시 물어보고 실행** |
| 화면 이해 | 없음 | **화면을 보고 설명하고 위치를 짚어 줌** |

> ⚠️ **이 표는 2024년 기준 자료로 만든 것입니다.**
> 2026년 현재 상태를 다시 조사하는 게 **과제 02**입니다.
> 특히 **Microsoft Copilot**이 Windows에 기본 탑재돼 있어서, 그게 실제로 PC를 조작하는지
> 아니면 답만 하는지가 **우리 프로젝트 정당성의 핵심**입니다.

---

## 4. 자랑할 만한 것 3가지

> 🔄 **2026-09-23에 순서가 바뀌었습니다.** 예전엔 ①이 «인터넷 없이도»였는데,
> 조사해 보니 **경쟁 제품도 오프라인이 기본**이라 «자랑»이 못 됩니다(기능으로는 여전히 참입니다).
> 대신 아래 ①이 **프로젝트의 정체성으로 확정**됐습니다 → [제품_방향 §1-A](../planning/제품_방향.md)

### ① 🧭 화면을 보고 길을 안내합니다 ← **여기가 우리 얼굴입니다**
*"블루투스 어디서 켜?"* 에 말로 설명하는 게 아니라 **설정을 열고 위치를 짚어** 줍니다.
👉 **대신 해 주는 게 아니라 사용자가 직접 하도록 돕는다**는 점이 다릅니다.

**한 문장으로**: *"어떻게 하는지 몰라도, 무엇을 원하는지만 말하면 됩니다."*

> 🚨 **말할 때 조심할 것 둘**
> - **«접근성 제품»이라고 하지 마세요.** 그렇게 말하면 *"실제 대상 사용자에게 시험했나요"* 를 묻는데,
>   **안 했습니다.** ***«접근성 문제에서 출발한 설계»*** 까지가 우리가 지킬 수 있는 말입니다.
> - **«기능이 44개나 됩니다»가 아니라 «외울 게 없습니다»** 로 말하세요.
>   경쟁 제품(Windows 음성 액세스)은 명령 문형이 **851줄**이고 토씨 하나 틀리면 안 됩니다.
>   우리는 사용자가 **외워야 하는 문형이 0개**입니다. 이게 개수로는 안 뒤집히는 차이입니다.

### ② 되돌릴 수 없는 일은 반드시 물어봅니다
파일 삭제, 화면 클릭, 전원 제어 — 이런 건 **실행 전에 사용자에게 확인**합니다.
*"a.txt와 b.txt 2개를 삭제할까요?"* 처럼 **무엇을 몇 개** 하는지 밝힙니다.

### ③ 인터넷 없이도 동작합니다
자주 쓰는 명령은 **학습돼서** AI 서버를 거치지 않고 바로 실행됩니다.
그래서 인터넷이 끊겨도 핵심 기능이 살아 있습니다.
📌 자랑거리는 맞지만 **«우리만 되는 것»은 아닙니다.** 그렇게 말하면 반박당합니다.

## 6. 어떻게 만들어졌나 (아주 간단히)

```
사용자가 말한다
   ↓
[음성 → 글자로 변환]        인터넷 있으면 Google, 없으면 컴퓨터 안에서 처리
   ↓
[이미 배운 명령인가?] ──── 예 ──→ 바로 실행 (빠름 · 인터넷 불필요)
   ↓ 아니오
[AI가 무엇을 할지 결정]     Google Gemini
   ↓
[위험한 동작인가?] ──── 예 ──→ 사용자에게 물어봄 → 승인하면 실행
   ↓ 아니오
[실행] → [결과 확인] → [사용자에게 답변 + 음성으로 읽어 줌]
```

**만드는 데 쓴 것들** (소개글 「주요 공개SW」 칸 재료)

| 용도 | 무엇 |
|---|---|
| AI 두뇌 | Google **Gemini 2.5 Flash** ⚠️ 옛 자료엔 «2.0»으로 적혀 있습니다. **2.0은 이미 없어진 모델**이라 그대로 쓰면 틀립니다 |
| AI 흐름 관리 | LangGraph |
| 음성 → 글자 | Google STT(온라인) · faster-whisper(오프라인) |
| 글자 → 음성 | edge-tts |
| 호출어 인식 | openWakeWord 기반 + 직접 학습시킨 모델 |
| 화면 창 | Electron |
| 서버 | FastAPI (Python) |

## 8. 용어 사전 — 문서에서 자주 보이는 말

| 용어 | 뜻 |
|---|---|
| **LLM / AI 모델** | 말을 이해하고 답을 만드는 인공지능. 여기선 Google Gemini |
| **STT** | Speech To Text. **음성을 글자로** 바꾸는 것 |
| **TTS** | Text To Speech. **글자를 음성으로** 읽어 주는 것 |
| **에이전트** | 단순히 답만 하는 게 아니라 **직접 행동하는** AI |
| **도구(tool)** | AI가 쓸 수 있는 기능 하나하나. "메모장 켜기" 같은 것. **45개** 있음 |
| **캐시** | 한 번 한 명령을 기억해 뒀다가 **다음엔 빨리** 처리하는 저장소 |
| **승인 / HITL** | 위험한 동작 전에 **사람에게 물어보는** 절차 (Human In The Loop) |
| **Vision** | 화면 그림을 AI가 보고 이해하는 것 |
| **웨이크워드 / 호출어** | "플루이즈" 처럼 **부르는 말** |
| **오버레이** | 다른 창 위에 항상 떠 있는 작은 창 |
| **리허설** | 실제로 말해 보며 처음부터 끝까지 시연해 보는 연습 |
| **BL-숫자** | 발견한 문제에 붙인 번호 (BL-01 ~ BL-56) |
| **mock 테스트** | 사람 없이 **자동으로** 기능이 멀쩡한지 검사하는 것 |
| **커밋 / 푸시** | 작업 내용을 저장하고(커밋) 인터넷 저장소에 올리는(푸시) 것 |
