## 🚫 «안 하기»로 정한 것 (2026-09-08) — 미룬 게 아니다

로드맵에서 **내렸다.** 10월까지 3주인데 다 하면 전부 어설프게 끝나기 때문이다.
*미루는 것과 «안 하기로 정하는 것»은 다르다* — 후자여야 **한계점 분석**이 된다.

| 안 하는 것 | 원래 시기 | 왜 안 해도 되는가 |
|---|---|---|
| **장기 메모리** | 10월 | *"쓸수록 알게 되는"* 축은 **캐시 동적 학습(P4)** 이 이미 대표한다 |
| **루틴 학습** | 10월 | 장기 메모리가 선행이라 그걸 안 하면 자동으로 따라간다 |
| **클라우드 동기화 · 로그인** | (구상) | *"인터넷 없이도 핵심 기능"* 이라는 **핵심 차별점과 정면으로 충돌**한다. Vision이 다루는 게 사용자 화면이라 프라이버시 설계가 졸작 범위를 넘어간다. 인증·서버·DB에 3주를 쓰면 포인팅도 웨이크워드도 못 한다 |

**대신 넣은 것**: `내보내기 / 가져오기` 파일 하나(캐시 + 메모리를 zip으로).
기기 이동 요구의 대부분이 해결되고, 심사에서 물으면
*"설계상 로컬 우선이고 이동은 파일로 합니다"* 가 **방어가 아니라 선택으로 들린다.**

**그 자리에 들어온 것**: ⭐ **포인팅 · 확대 + 설정창 길안내**(2주차 메인).
`find_ui_element`가 이미 화면 좌표를 주고 Electron에 오버레이가 있어 **싸고**,
아무것도 바꾸지 않아 **승인이 필요 없다.** 클릭 자동화가 *대신 해 주는* 것이라면
포인팅은 *사용자가 직접 하게 돕는* 것이라 **범용 에이전트가 대체하지 않는 자리**다.

> ⚠️ **병렬 실행은 여기 없다.** 그건 «안 함»이 아니라 **조건부 보류**다 —
> BL-20을 고친 뒤 **읽기 전용 도구에 한해** 재검토한다([M3 §5-2](design/M3_계획수립노드.md)).

3주 계획(1주 웨이크워드 · 2주 포인팅 · 3주 임베딩 캐시 + 도구 실측)의 체크리스트는
[TASKS.md](TASKS.md) ②에 있다. 근거 전문은 `docs/planning/제품_방향.md`(🔒 로컬 전용).

   > **지켜보기(`watch_screen`)** 가 이어졌다. 도구 27개 → **40개**,
   > 승인 필수 도구 2 → **3개**.
   > ✅ **2026-09-07 — 다섯 기능 전부 실기 확인. Phase 2가 진짜로 닫혔다.**
   > 좌표 클릭은 승인 후 실제로 눌렸고(없는 요소는 거절), 화면 감시는 알림 도달 ·

   > 세고 캐시에 학습되던 것)과 BL-22(프리필터가 타이핑을 못 보던 것)를 고쳤다.

### RAG 문구를 정정한 이유

루트 [`README.md`](../README.md)와 [`docs/README.md`](README.md)가 강의 개념을
*"LangGraph · HITL · OWASP Guardrail · **RAG**"* 로 나열해 **이미 적용한 것처럼** 읽혔다.
그러나 `rag|embedding|vector|chroma|faiss|retriev` 전수 검색 결과 **코드 0건**이다.

커맨드 캐시가 유사도 검색(difflib 0.80)을 하지만 그건 retrieval이지 RAG가 아니다 —
검색 결과를 LLM 컨텍스트에 넣어 생성하는 구조가 아니라 **캐시 히트 시 LLM을 건너뛴다.**

이 프로젝트에서 RAG는 위 매핑표대로 **"캐시의 문자열 유사도를 임베딩 유사도로 교체"** 를
뜻하며, 그건 로드맵 **10월(임베딩 기반 캐시 · 장기 메모리)** 항목이다.
→ 두 README에서 RAG를 빼고, 10월에 도입 여부를 판단한다.

> 심사에서 *"RAG 적용하셨나요?"* 를 받으면: **"캐시 시맨틱 매칭으로 10월에 적용 예정이고,
> 현재는 문자열 유사도(difflib 0.80)로 동작합니다"** 가 정확한 답이다.
