## 2. 개발 프로세스

### 2.1 프로세스 모형
**점진적 모델(Incremental Model)** 을 채택한다.

- 채택 근거: 본 프로젝트는 **요구사항 변경이 빈번하게 발생**했다.
  실제로 1학기 데모 이후 웨이크워드 방식·에이전트 구조·캐시 매칭 방식이 각각 한 번 이상 교체되었다.
- 각 스프린트마다 동작하는 시스템을 산출하고, 실기 검증에서 나온 결함을 다음 스프린트 범위에 반영한다.

### 2.2 개발 절차
⬜ TODO(그림) — 점진적 모델 그림 1장. 팀원 과제로 배정 가능

실제 운영 절차:
`요구사항 식별 → 스프린트 백로그 작성 → 구현 → 자동화 테스트(mock) → 실기 리허설 → 결함 기록(BACKLOG) → 다음 스프린트 반영`

> 🔑 이 프로젝트의 특징: **자동화 테스트가 전부 통과해도 실기에서 결함이 나온다**는 것을
> 반복 관측했고(BL-17·BL-30·BL-50~53), 그래서 **리허설을 절차에 고정**했다.
