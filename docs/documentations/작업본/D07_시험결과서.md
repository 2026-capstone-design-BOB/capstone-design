## 2. 테스트 개요

### 2.1 테스트 범위

본 과정에서는 단위 테스트와 통합 테스트를 별도 단계로 분리하지 않는다.
**최종 구현된 시스템 전체에 대하여 시스템 테스트를 수행한다.**
[D04 프로덕트 백로그](D04_프로덕트백로그.md)에 제시된 모든 요구사항이 테스트 대상이다.

**제외 항목과 그 사유** (양식이 명시를 요구한다):

| 제외 항목 | 사유 |
|---|---|
| Gemini API 응답 **내용**의 정확성 | 외부 LLM 서비스의 출력이며 본 시스템의 구현 범위가 아니다. 단, **도구 선택 결과**는 테스트 대상에 포함한다 |
| Google STT의 **인식 정확도** | 외부 서비스의 성능이다. 단, **온라인/오프라인 전환 동작**은 테스트 대상이다 |
| TTS 음성의 **음질·억양** | edge-tts의 출력 품질이다. 단, **재생 여부와 중복 재생 방지**는 테스트 대상이다 |
| 웹 검색 결과 **문서의 내용** | 외부 웹 콘텐츠다. 단, **검색을 실제로 수행했는지**와 **실패를 성공으로 보고하지 않는지**는 테스트 대상이다 |
| Windows OS 자체의 동작 | 앱 실행·창 제어의 최종 수행 주체는 OS다. 단, **호출 전 조건 확인**과 **결과 검증**은 테스트 대상이다 |
| 내장 마이크·스피커의 **하드웨어 성능** | 테스트 PC 고유의 특성이다. §5.1에 사양을 명시하는 것으로 대체한다 |

> 🔑 이 프로젝트는 **자동화 테스트(mock)와 실기 검증을 모두 수행**했다.
> mock은 외부 의존을 대체하여 로직을 검증하고, 실기 리허설은 사람이 마이크 앞에서 수행한다.
> **둘을 구분하여 기술하는 것이 이 문서의 강점이 된다** — 실제로
> «mock이 전부 통과했는데 실기가 결함을 잡은» 사례가 반복 관측되었다
> (2026-09-10 BL-17·BL-30, 2026-09-12 BL-50~52, 2026-09-14 BL-53·54).

### 4.1 중단 기준과 재개 조건 (표 4)
