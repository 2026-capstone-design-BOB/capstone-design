### BL-09 — 노출된 Gemini API 키 폐기 (사용자 조치 필요)
> **상태**: 소스에서는 제거 완료. **키 폐기만 남음 — 2026-09-01 사용자가 의식적으로 보류.**

- **무슨 일**: `tests/test_sensitive.py`의 마스킹 테스트가 실제 형식 Google API 키
  (`AIzaSyClLQ`로 시작)를 하드코딩하고 있었고, `.env.example`에도 같은 값이 있었다.
  `main` 브랜치까지 푸시된 상태였다.
- **조치 완료**:
  - `1d2ca22` — 테스트의 키를 명백한 더미(`AIzaSyFAKE...`)로 교체
  - `a244d7e` — `.env.example`을 플레이스홀더로 재작성
  - CI `secret-guard` 잡 추가로 재발 방지
- **남은 것 (사용자)**: [Google AI Studio](https://aistudio.google.com/apikey)에서
  `AIzaSyClLQ`로 시작하는 키 **삭제(revoke)**.
- **왜 이력 재작성이 아니라 폐기인가**: 키는 git 이력에 남아 있다
  (`git log --all -S'<키>'`로 확인 가능). 이미 푸시된 커밋이라 `filter-repo`로
  지우려면 전체 이력 재작성 + 강제 푸시가 필요하고 협업 브랜치가 깨진다.
  **키를 폐기하면 이력에 남아 있어도 무의미해지므로 훨씬 간단하고 확실하다.**
- **폐기해도 안전한 이유**: 현재 `.env`는 다른 키(`AQ.Ab8R`로 시작)를 쓰고 있어
  이 키를 삭제해도 앱 동작에 지장이 없다. (2026-09-01 확인)
- **우선순위 판단 시 확인할 것**: 저장소가 public이면 즉시 처리. private이면 상대적으로
  급하지 않으나, 졸업 후 공개 전환 시 반드시 먼저 폐기할 것.
- **발견**: 2026-09-01 (CI secret-guard 잡을 로컬 재현하다 발견)
