## 3. 이 프로젝트가 스스로에게 건 규율

교수님께 가장 보여드리고 싶은 부분입니다. 기능 개수보다 **이쪽이 프로젝트의 성격**입니다.

### 3-1. *"안 한 걸 안 했다고 말한다"*

에이전트 시스템에서 가장 위험한 실패는 **에러가 아니라 거짓 성공**입니다.
반복해서 데였고, 그때마다 **프롬프트가 아니라 구조로** 막았습니다.

| 사고 | 무엇이 일어났나 | 어떻게 막았나 |
|---|---|---|
| BL-12 | 글자 입력 도구가 **엉뚱한 창**에 넣고 *"✓ 입력 완료"* | 입력 **전에** 대상 창을 확인하고, 못 잡으면 넣지 않는다 |
| BL-15 | 캐시가 문장 앞부분만 처리하고 뒷부분을 **조용히 버림** | 해석 못 한 잔여 명령이 있으면 **캐시를 포기**한다 |
| BL-19 | 감시 도구를 **부르지도 않고** *"지켜볼게요"* 라고 답함 | 도구 실행 **상태**로 판정 + 재시도를 `tool_choice` **강제**로 |
| BL-21 | 계획이 **건너뛴 단계를 완료로 기록**하고, 그게 **캐시에 학습**됨 | `min(커서, 실제 도구 호출 수)` — **덜 낙관적인 쪽**을 믿는다 |
| — | 삭제해 놓고 *"취소했어요"* 라고 오보 | 취소 플래그가 턴을 넘어 새지 않게 구조로 차단 |

> **핵심 문장**: *"프롬프트는 확률을 올릴 뿐이고, 보장하는 것은 구조다."*
> 실측 근거가 있습니다 — 같은 코드 · 같은 temperature인데 시간대에 따라 도구 호출률이
> **10/10에서 0/10까지** 흔들렸습니다. 설득으로는 못 막습니다.

| **아는 것은 안 보고 한다** | 앱 실행을 **네이티브 Windows API**로 부릅니다. 창 목록을 *보는* 게 아니라 **압니다.** 캐시 히트면 **LLM 0회 · 0.2초** | 매 스텝 스크린샷을 클라우드로 전송 |
| **인터넷이 끊겨도 돈다** | 캐시 + 오프라인 STT 폴백 | 불가능 |
| **안 한 걸 안 했다고 말한다** | 도구 실행 **상태**로 판정 (§3-1) | 없음 |
| **정직한 약점 — 범용성** | 39개 도구가 덮는 것만 | 무엇이든 |

> **한 문장**: *"computer use는 무엇이든 하지만 매번 화면을 봐야 하고,
> Pluiz는 아는 것은 즉시 하고 모르는 것만 봅니다."*

**⚠️ 이 서사가 심사에서 통하는지가 §6-④의 질문입니다.**

## 6. ⏸️ 교수님께 여쭙고 싶은 것

각 항목에 **현재 기울어 있는 답**을 같이 적었습니다. 판단만 해 주시면 바로 진행합니다.

### ① 사용자 데이터를 클라우드로 올릴 것인가

**배경**: *"사용자에 맞게 최적화되고 기억하는 것"* 이 서비스 기능이라면 그 데이터를
PC뿐 아니라 클라우드에서 관리해야 하는 것 아닌가 — 그러면 **로그인 시스템**도 필요합니다.

> **기울어 있는 답: 하지 않기.** 세 가지 이유입니다.
> ① **정체성과 충돌**합니다 — *"인터넷 없이도 핵심 기능"* 을 핵심 차별점으로 잡았는데
>    클라우드 동기화는 정반대 방향입니다.
> ② **화면 데이터가 얽힙니다** — Vision이 다루는 게 사용자 화면입니다. 서버에 두는 순간
>    프라이버시 설계가 졸작 범위를 넘어갑니다.
> ③ **본체가 죽습니다** — 인증·서버·DB에 3주를 쓰면 포인팅도 웨이크워드도 못 합니다.
>
> **대안**: `내보내기 / 가져오기` 파일 하나(캐시 + 메모리를 zip으로). 기기 이동 요구의
> 대부분이 해결됩니다.

**여쭐 것**: 심사 기준에서 **클라우드·로그인이 있어야 가점**이 되는지, 아니면
*"설계상 로컬 우선"* 이 **선택으로 인정**되는지.

### ② 무엇을 «안 하기»로 정할 것인가

10월까지 3주입니다. 다 하면 전부 어설프게 끝납니다.
**미루는 것과 «안 하기로 정하는 것»은 다릅니다** — 후자여야 한계점 분석이 됩니다.

**후보**: 장기 메모리 · 루틴 학습 · 클라우드 동기화

**여쭐 것**: 졸작 평가에서 **기능 개수**와 **완성도** 중 어느 쪽이 무겁게 평가되는지.

### ③ 포인팅 · 확대(접근성)를 프로젝트의 얼굴로 올릴 것인가

**배경**: *"노안이나 저시력을 위해 «그게 어딨지» 하면 확대하거나 포인팅해 주는 기능"*.
그리고 *"설정창 들어가면 헤매는데 그것도 도와줄 수 있나"*.

> **기울어 있는 답: 올리기를 권합니다.**
> ① **카테고리가 다릅니다.** 클릭 자동화는 *대신 해 주는* 것이고, 포인팅은
>    *사용자가 직접 하게 돕는* 것입니다. 범용 에이전트가 대체하지 않는 자리입니다.
> ② **거의 만들어져 있습니다.** `find_ui_element`가 이미 **화면 좌표**를 반환하고,
>    Electron에 always-on-top 오버레이 창이 이미 있습니다. 남은 건 그 좌표에
>    표시를 그리는 것입니다.
> ③ **위험이 0입니다.** 클릭은 되돌릴 수 없어 승인이 필요하지만, **포인팅은
>    아무것도 바꾸지 않으므로 승인이 필요 없습니다.**

**여쭐 것**: 접근성 보조라는 **응용 방향**이 졸작 주제로서 설득력이 있는지.

### ④ computer use와의 차별화 서사가 통하는가

§5의 표와 한 문장이 심사에서 **방어가 되는지**, 아니면 *"결국 못 하는 게 더 많은 것"* 으로
읽히는지. **읽히는 쪽에 따라 남은 3주의 배분이 달라집니다.**

### ⑤ RAG(임베딩 캐시)를 꼭 채워야 하는가

강의 개념 매핑에서 **RAG만 유일하게 미적용**입니다. 현재 캐시는 문자열 유사도
(difflib 0.80)이고, 이걸 임베딩 유사도로 바꾸는 것이 이 프로젝트에서의 RAG입니다.

> 다만 정확히는 **retrieval이지 RAG가 아닙니다** — 캐시가 히트하면 LLM을 **건너뛰기**
> 때문에, 검색 결과를 컨텍스트에 넣어 생성하는 구조가 아닙니다.
> (문서에 *"RAG 적용"* 이라고 잘못 적혀 있던 것을 2026-09-02에 정정했습니다)

**여쭐 것**: 강의 개념 커버리지를 위해 **넣는 것이 나은지**, 아니면 위 설명대로
*"구조상 RAG가 아니다"* 를 근거로 **빼는 것이 정직한지**.

### ⑥ 팀 브랜치 처리 — `feature/ohdayoung`

2026-06-07 이후 멈춰 있고, 코드 **7,606줄**이 전부 **2026-09-01에 제거된 옛 폴더 구조**
위에 있습니다. 병합 충돌이 아니라 **서로 다른 프로젝트 둘**입니다.

**선택지**: ① 팀원이 새 구조로 이전 ② 폐기 ③ 그대로 둠

**여쭐 것**: 기여도·협업 평가 관점에서 어떻게 처리하는 것이 맞는지.

## 부록 A — 시스템 구조

```
사용자 입력 (음성 /voice · 텍스트 /chat · /ws)
  │
  ├─ 0층: 토큰 검사 (없으면 401)
  ├─ 1층: 규칙 기반 보안 검사
  │
  └─ LangGraph StateGraph
        │
     START → input_guard ─(차단)────→ output_guard → END
                │
                ▼
             fast_path ─(캐시 히트)──→ output_guard → END      ← LLM 0회 · 0.2초
                │(미스)
                ├─(복합 명령)────→ planner ─┐
                │                            ▼
                └────────────────────→ agent ⇄ tools ──→ output_guard → END
                                        │ ▲       │
                                        │ │       └─(못 믿을 도구)→ visual_verify
                                        │ └(계획에 남은 단계)
                                        └─(위험 도구)→ hitl (사람 승인)
```

| 노드 | 역할 |
|---|---|
| `input_guard` | 코드 레벨 보안 검사 |
| `fast_path` | 캐시 + 결정론적 라우터 — **히트해도 결과를 대화 기록에 남긴다** |
| `planner` | 복합 명령을 **최대 2단계**로 나눠 상태에 적는다 (실행은 하지 않음) |
| `agent` | LLM 추론. 계획이 있으면 **지금 실행할 단계만** 지시받는다 |
| `tools` | 도구 실행 |
| `hitl` | 위험 도구 실행 전 **사람 승인** (그래프가 멈춘다) |
| `visual_verify` | 도구 결과를 **화면으로** 확인해 증거를 붙인다 |
| `output_guard` | 빈 응답 복구 + **아무 일도 안 일어난 턴은 "실행했다"고 하지 않는다** |

| 역할 | 기술 |
|---|---|
| AI 에이전트 | LangGraph `StateGraph` + Gemini 2.5 Flash (provider 전환 가능) |
| STT | Google STT(온라인) + faster-whisper(오프라인 폴백) |
| TTS | edge-tts |
| 서버 | FastAPI + uvicorn (:8765) |
| UI | Electron frameless 오버레이 |
